# 从 domain 层入手逐模块讲解代码库（小白向）

## 何时使用

用户说「讲讲这个项目 / 从某个层开始挨个模块讲 / 我不懂编程，讲明白点」时使用。
默认入口是 **domain 层**，因为它是全项目最纯的一层（只依赖 JDK），最适合初学者建立心智模型。

## 固定讲解顺序（讲完一个再讲下一个，不要一次全倒出来）

域内顺序（由「底层原语」到「业务主角」，后一个依赖前一个）：

| 序 | 模块 | 包 | 一句话理由 |
|---|---|---|---|
| 1 | 共享内核 | `domain.shared` | 所有模块都要用的「积木」：ID、错误、校验 |
| 2 | 会话 | `domain.session` | 全系统的中心：消息怎么存、怎么拼给模型 |
| 3 | 模型 | `domain.model` | 会话要发给谁：档案 + 调用契约 |
| 4 | 工具 | `domain.tool` | 模型想动手：工具描述、调用、结果 |
| 5 | 治理 | `domain.governance` | 动手术前先过安检：策略、审批、沙箱 |
| 6 | 运行时 | `domain.agent` | 把上面四者串成一圈：Run 状态机与预算 |
| 7 | 上下文 | `domain.context` | 太长怎么办：token 估算、压缩、Skills |
| 8 | 扩展 | `domain.extension` | 别人怎么插进来：插件安装与兼容 |
| 9 | 子代理 | `domain.subagent` | 递归自己：深度、工具子集、沙箱交集 |

跨层顺序（domain 讲完后）：application（用例与 Agent Loop）→ infrastructure（适配器）→ trigger（HTTP/CLI）→ app（装配）。
每个层讲完必须给一张「上一层的哪个接口由这一层的哪个类实现」的对照表，否则初学者会失去线索。

## 每个模块必须交付的 7 段结构

1. **一句话定位**：这个模块在整个系统里干什么，用生活化类比（例如「身份证工厂」「门禁系统」）。
2. **要解决的现实问题**：不讲抽象 DDD，先讲「如果不这么做会出什么事」，用反例衬托设计。
3. **原理**：机制本身怎么工作，必要时配 ASCII 图或表格；凡涉及算法（ULID、投影回溯、压缩切点）都手算一个小例子。
4. **怎么实现的**：文件清单 + 责任分工 + 模块内「model / service / port」的划分逻辑，解释为什么这样切。
5. **核心代码**：贴关键片段（来自真实文件，带路径与行号），逐行注释，重点讲「为什么这样写」。
6. **依赖了哪些其它层**：分成三栏——
   - 向下依赖：本模块用了谁（domain 内部通常只有 `shared`）；
   - 向上被谁实现：本模块定义的 port 接口由哪个模块的哪个类实现（给出真实类名）；
   - 契约约束：依赖方向规则（domain 仅 JDK）与本模块的禁止事项。
7. **自测题 + 测试在哪**：给 2~3 个检查理解的小问题，并指出对应单测路径（`src/test/java/...`），让读者能自己跑。

## 对编程小白的表达规则

- 首现术语必须解释：聚合根、值对象、record、sealed、枚举、端口/适配器、不可变、乐观锁、CAS、纯函数。
- Java 语法点（`record`、`@FunctionalInterface`、compact constructor、`enum`、`Optional` 等）单列「语法小抄」小块，不混进业务解释。
- 不省略「为什么」：每个设计决策补一句「如果不这样，会发生 X」。
- 类比要单一且贯穿本节，不要同段换三个类比。
- 代码只贴必要片段，长文件给 `路径:行号`，让读者自己打开看。
- 结尾必须留「下一步讲什么」的一句话，保持连续性。

## 证据要求（防编造）

- 讲任何类前先 `read` 真实文件；引用代码必须与文件内容一致。
- 不允许凭文档描述讲实现：文档说「M4 不可变快照」，也要打开 `AgentRun.java` 验证。
- 文档与代码冲突时以代码为准，并在讲解里点出差异。
- 不确定的类名/方法名，先用 `grep` 确认再写。

## 产出模板骨架

```markdown
## 第 N 讲：<模块名>（domain.<包>）

### 0. 一句话定位
### 1. 为什么需要它（反例先行）
### 2. 原理（图 + 小例子）
### 3. 实现拆解（文件清单表）
### 4. 核心代码逐段讲
### 5. 依赖关系（向下 / 向上被实现 / 契约约束）
### 6. 语法小抄（本节涉及的 Java 写法）
### 7. 自测题 & 测试位置
> 下一讲预告：...
```

## 进度台账

每讲结束后更新 `docs/tutorial-progress.md`，记录：已讲模块、遗留疑问、下一讲。
放在 `docs/` 而不是 skill 目录，因为进度属于仓库文档，不属于可复用的技能定义。
