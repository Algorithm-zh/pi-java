# 00 愿景与范围

> 状态：M0 冻结。本文定义 pi-java 的产品边界，后续里程碑不得悄然扩大 v0.1 的范围。

## 1. 一句话定位

**pi-java 是一个用 Java 21 实现的、单机优先、日志驱动的插件化 coding agent。**
它保留 pi “小内核 + 可扩展”的骨架，用 DDD 明确边界，并吸收 DeepSeek Harness 在审批、沙箱、失败处理和子代理权限上的工程经验。

它不是聊天框套壳，也不是工作流编排平台。它的核心只有一件事：
**把用户意图、模型输出、工具调用与结果，可靠地记录成一棵可回溯的会话树，并推动下一轮推理。**

## 2. 为什么要重写

| 动机 | 说明 |
|---|---|
| 验证 pi 的抽象 | pi 的 agent loop、会话树、扩展与压缩设计足够克制，值得用强类型语言重新表达 |
| Java 工程化 | 企业环境更熟悉 JVM、Spring Boot、MyBatis、MySQL；需要可观测、可运维的落地形态 |
| 修正常见 DDD 误区 | 避免领域模型被 Spring/Jackson/MyBatis 注解污染，避免“一个大 Service + 一张大表” |
| 引入治理能力 | 工具审批、路径沙箱、子代理权限约束必须在运行时是一等公民，而不是事后补丁 |
| 可测试 | LLM、工具、时间、ID、文件系统全部通过端口注入，离线即可完成端到端测试 |

参考对象：

- pi（TypeScript）：agent loop、JSONL 树形会话、compaction、skills、extension API；
- DeepSeek Harness：append-only 事件日志、插件生命周期、工具管线、默认只读沙箱、子代理权限不放大。

## 3. 设计原则

1. **会话日志是唯一事实源。**
   对话、压缩摘要、审批决策、运行摘要全部是 entry；不维护第二份可变的“当前消息数组”。
2. **小内核，插件扩展。**
   内核只认识 `ToolDescriptor`、hook 与 prompt section；第三方能力通过零依赖插件 API 接入。
3. **领域纯净。**
   `domain` 只依赖 JDK；路径解析、JSON、SQL、HTTP、Spring 全部留在外层。
4. **安全默认。**
   只读工具默认放行，写工具默认询问，未知工具默认拒绝；密钥只从环境变量读取。
5. **本地优先，单机强一致。**
   v0.1 不引入 Redis、消息队列和分布式锁；同一会话同一时刻只有一个活跃 run。
6. **失败可解释。**
   LLM 错误、工具失败、审批超时、用户取消都有明确 stopReason 与持久化记录，不吞异常。
7. **小步交付。**
   每个里程碑包含实现、测试、文档与提交；任何时刻仓库都应可构建、可运行。

## 4. v0.1 范围

| 能力 | 包含 | 说明 |
|---|---|---|
| Agent Loop | 是 | 多轮推理、流式输出、工具循环、最大步数、取消 |
| 会话 | 是 | 树形 entry、分支、fork、上下文投影、运行摘要 |
| 模型 | 是 | Fake 确定性模型 + OpenAI-compatible 流式适配器 |
| 工具 | 是 | `read`、`ls`、`grep`、`glob`、`write`、`edit`、`bash`、`subagent` |
| 治理 | 是 | 工具策略、人工审批、路径沙箱、参数脱敏、超时 |
| 上下文 | 是 | 结构化压缩、token 估算、保留尾部、摘要不收敛回退 |
| Skills | 是 | `SKILL.md` 扫描、frontmatter、按需加载、`/skill:name` |
| 插件 | 是 | 零依赖 SDK、工具注册、类加载隔离；命令/hook/prompt section 视后续里程碑 |
| 子代理 | 是 | 同步、进程内、SPAWN/FORK、深度与工具子集约束 |
| 入口 | 是 | REST + SSE、原生 Web UI、picocli CLI |
| 持久化 | 是 | MySQL 8 与 H2（MySQL 模式）、Flyway 分厂商脚本 |
| MCP | 否 | v0.2 评估 |
| Anthropic 原生 | 否 | 预留 `LlmGateway` SPI |
| 多实例 / Redis | 否 | 单机部署；未来通过端口扩展 |
| 异步/并行子代理 | 否 | 只做同步子代理 |
| 插件热重载 | 否 | 停用立即移出工具目录；旧实例与类加载器保留到进程退出 |
| 多模态输入 / TUI | 否 | v0.1 只处理文本 |

## 5. 非目标

- 不做通用工作流引擎、RPA 平台或低代码编排器。
- 不承诺恶意插件安全隔离；类加载隔离不等于安全沙箱。
- 不提供公网多租户能力；v0.1 默认本机单用户运行，无鉴权。
- 不覆盖 pi 的全部 provider、全部扩展事件与全部 UI 能力。
- 不以“兼容 pi 的所有会话文件”为目标；只借鉴其树形会话与压缩语义。

## 6. 用户故事

| 编号 | 角色 | 故事 | 验收要点 |
|---|---|---|---|
| US-01 | 开发者 | 我想在浏览器里新建会话并看到逐字流式回复 | SSE 增量、断线可恢复、失败有提示 |
| US-02 | 开发者 | 我想让 agent 读取仓库文件并解释代码 | 只读工具无需审批，路径不越界 |
| US-03 | 开发者 | 我想在 agent 写文件前批准或拒绝 | 审批弹窗、超时/取消、决策可审计 |
| US-04 | 开发者 | 我想回到某个历史节点重新提问 | 树形分支不复制历史、可对比不同分支 |
| US-05 | 开发者 | 长会话不要因上下文超限而中断 | 自动压缩、工具调用与结果不被拆散 |
| US-06 | 开发者 | 我想用团队规范扩展 agent | 安装插件后出现新工具/命令，禁用即消失 |
| US-07 | 开发者 | 我想把大任务拆给受限的子代理 | 子会话可追踪、工具是父集合子集、可取消 |
| US-08 | 运维/测试 | 我想在没有 API Key 的情况下跑通全链路 | Fake 模型可脚本化流、工具调用与错误 |

## 7. 成功标准

v0.1 发布必须同时满足：

1. `mvn -q verify` 全绿：单测、H2 集成测试、ArchUnit、Checkstyle、JaCoCo 门槛。
2. `demo` profile 下浏览器完成：新建会话 → 流式回复 → 只读工具 → 审批写文件 → 取消运行 → 查看分支。
3. CLI 完成同一链路的简化版。
4. 配置 `DEEPSEEK_API_KEY` 后能真实完成一次“读文件 + 改文件”的任务。
5. 本机 MySQL 8 通过 Flyway V1–V5 并跑通一条会话。
6. 示例插件安装、调用、禁用全链路可用，运行中的 run 不受卸载影响。
7. 父会话调用子代理，子会话只拥有父工具子集，结果回写父会话。
8. 文档与里程碑记录完整，git 历史可读，打 tag `v0.1.0`。

## 8. 术语

| 术语 | 含义 |
|---|---|
| Session / 会话 | 一棵 entry 树；同一时刻只有一个 leaf |
| Entry | 只追加、不可修改的日志节点；消息、摘要、审批等都是一种 entry |
| Leaf | 当前分支末端，决定下一次投影的起点 |
| Projection / 投影 | 从 leaf 回溯并应用压缩语义，得到发给 LLM 的消息序列 |
| Run | 一次用户请求驱动的执行过程，从创建到 COMPLETED/FAILED/ABORTED |
| Turn | Run 内一次 LLM 请求及其产生的工具调用阶段 |
| Tool Call | 模型请求执行某个工具的结构化调用 |
| Approval | 对高风险工具调用的显式人工决策 |
| Compaction | 用结构化摘要替换较早上下文，同时保留近期尾部 |
| Skill | 带 frontmatter 的 `SKILL.md`，按需加载的领域知识与工作流 |
| Plugin | 通过 `pi-java-plugin-api` 注册工具/hook/命令的第三方扩展 |
| Subagent | 以子会话形式运行的同步代理，权限不高于父代理 |
