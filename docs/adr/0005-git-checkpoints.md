# ADR 0005：用临时索引做工作区检查点，不碰用户分支

- 状态：Accepted
- 日期：2026-10-25
- 决策者：pi-java 架构

## 背景

M13 需要让代理在改坏工作区后能一键退回，同时不能干扰用户自己的 Git 状态。
具体需求：

1. run 前记录工作区，turn 后能看到改了什么；
2. 撤销上一轮时文件与对话一起退回；
3. 未跟踪文件也要纳入；
4. 绝不能创建分支、移动 HEAD、改写用户索引或自动提交；
5. 工作区不是仓库、没装 git 时必须优雅降级，不能打断 run。

候选方案：

- **真实分支 + 自动提交**：历史清楚，但会污染用户分支与提交记录，撤销需要 reset，
  风险高；
- **git stash**：会改用户索引与 stash 栈，且未跟踪文件需额外参数，失败恢复复杂；
- **复制整个目录**：实现简单，但大仓库磁盘与 IO 成本不可接受，还容易漏 `.git`；
- **JGit / libgit2**：无需外部进程，但引入大依赖，且与用户仓库的配置兼容性需要
  自己维护；
- **临时索引 + 树对象**：只读仓库、只写对象库，实现可完全基于本机 git CLI。

pi-java 的工具体系已经接受“依赖本机 git 可执行文件”的假设；检查点应当是旁路
观察者，而不是仓库状态的参与者。

## 决策

定义领域端口 `WorkspaceGit`，infrastructure 用 git CLI 实现；所有快照与还原都
通过 `GIT_INDEX_FILE` 指向临时索引：

```text
快照：read-tree <HEAD|empty> → add -A --ignore-errors → write-tree
还原：read-tree <baseTree> → checkout-index -f -- <path>
```

- 快照得到树对象 `treeSha`，与 `headSha`、`branch` 一起写入 `GIT_CHECKPOINT` entry；
- 每轮结束再快照一次，与上一轮树对象比较，差异写入 `GIT_CHANGES` entry；
- 撤销时先比对“本轮路径的当前 blob 是否仍等于本轮结束 blob”，有冲突就整体放弃；
- 无冲突时只还原本轮改动过的路径，再把会话叶子退回到检查点记录的 `baseLeafId`；
- 写入与还原都带 `core.autocrlf=false`，保证 JSON 记录的对象与工作区字节一致；
- 第一轮撤销清空 entry 日志，满足“根 entry 必须是 seq=1 且 parent=null”的领域约束；
- Git 命令失败、超时、非仓库都只降级为“没有 Git 信息”，不影响 run。

## 结果

正面：

- 用户分支、HEAD、索引、提交历史完全不变，撤销前后 `git status` 语义一致；
- 未跟踪文件天然纳入（`add -A`），`.gitignore` 继续生效；
- 检查点与改动是普通会话 entry，重启后仍能查询与撤销，不依赖内存；
- 不需要 JGit 等额外依赖，行为与用户本机 git 配置一致；
- 冲突预检保证“要么全退，要么不动”，不会出现半还原。

负面：

- 每次快照都要扫描工作区，超大仓库有 IO 成本；
- 树对象没有任何 ref 指向，`git gc --prune=now` 后旧检查点不可还原；
- 重命名被当作删除 + 新增，空目录可能残留；
- 只能撤销最近一次 run，不支持任意检查点；
- 依赖本机 git 可执行文件与 Windows 进程启动开销；
- 子模块只作为 gitlink 参与快照，内部内容不还原。

## 边界

- 不创建 commit、branch、tag，不执行 `reset --hard`、`checkout`、`stash`；
- 不修改用户的 `.git/index`，所有索引操作都指向临时目录；
- 不在检查点里保存文件内容副本，只保存树对象引用；
- 不把 Git entry 放进模型上下文（`tokenEstimate=0`，投影器跳过）；
- 撤销只处理最近一次 run 的改动路径，其余文件一律不动；
- 冲突不自动合并、不写 `.orig` 文件，交由用户决定。

## 替代方案

### 真实分支 + 自动提交

可读性最好，但每个 turn 都产生提交会污染历史；撤销依赖 reset，容易误伤用户
未提交改动。与“代理只是工作区参与者”的定位冲突，不采用。

### git stash

需要改用户索引与 stash 栈，多个会话并发时难以区分归属；恢复失败时的兜底路径
比临时索引复杂，不采用。

### 目录复制

对小项目可行，但对包含 `node_modules`、`target` 的仓库成本过高；还会复制
`.git` 或漏掉被忽略文件，语义不清晰，不采用。

### JGit

可以避免外部进程，但引入较大依赖且需自行处理用户 git 配置差异；v0.2 暂不采用，
若未来需要跨平台一致性再评估。
