# v0.2.0 发布说明

> 版本：0.2.0
> 日期：2026-10-26
> 状态：已发布（2026-10-26）；Git tag 与 GitHub Release 已创建

## 新增能力

### MCP 客户端（M12）

- 支持 stdio 与 Streamable HTTP 两种传输，启动时动态发现 `tools/list`；
- 服务名作为命名空间，工具名形如 `server.tool`，避免与内置工具冲突；
- 工具风险可显式配置或自动推断；断线、超时、崩溃时返回明确错误；
- Web 工具菜单与 CLI 均可调用 MCP 工具。

### Git 感知与检查点（M13）

- run 前为工作区拍快照，逐轮计算 diff，展示文件与行数变化；
- “撤销本轮”只还原本轮改动的文件并回退对话，不修改分支、HEAD 或提交历史；
- 未跟踪文件与冲突场景有明确提示；工作区不是 Git 仓库时自动跳过。

### 计划、待办与自动验证（M14）

- 新增 `todo` 工具：整表替换计划，最多 20 项、至多一个 `in_progress`；
- 计划写入会话日志（`PLAN` entry），切分支、撤销、重启后仍可恢复；
- 改过工作区的 run 在收尾前执行一次 `pi.verify.command`，失败输出回传模型修复，
  每个 run 只回写一次；
- Web 待办面板与 CLI `[待办]` / `[验证]` 摘要共用同一事件源。

### 工程化（M15）

- GitHub Actions：`mvn verify`、Docker 构建与容器 smoke、MySQL profile smoke；
- 多阶段 `Dockerfile`：非 root 运行、数据卷与工作区分离、内置健康检查；
- `docker-compose.yml`（H2）与 `docker-compose.mysql.yml`（MySQL 叠加）；
- springdoc OpenAPI：`/v3/api-docs` 与 `/swagger-ui.html`；
- 版本号统一升级为 `0.2.0`。

## 升级说明

- 从 0.1.x 升级不需要数据库迁移；v0.2 未新增 Flyway 脚本；
- 构建产物改名为 `pi-java-app/target/pi-java-app-0.2.0.jar`；
- 新增可选配置：
  - `pi.mcp.servers`：MCP 服务器列表；
  - `pi.git.*`：检查点开关与超时；
  - `pi.verify.*` 与 `PI_VERIFY_COMMAND`：自动验证；
  - `PI_DATA_DIR`：H2 数据目录（容器默认 `/app/data`）；
- 原有 API 路径、CLI 子命令与 DTO 字段保持兼容，只新增字段与端点。

## 启动方式

本机：

```bash
mvn -q -DskipTests package
java -jar pi-java-app/target/pi-java-app-0.2.0.jar
```

Docker：

```bash
docker build -t pi-java:0.2.0 .
docker run --rm -p 127.0.0.1:8080:8080 \
  -v "$PWD:/workspace" -v pi-data:/app/data pi-java:0.2.0
```

Compose：

```bash
docker compose up --build
```

详见 [14 部署、容器与 CI](../14-deployment.md)。

## 验证

- `mvn verify`：770 个测试通过，2 个符号链接用例按平台跳过；
  Checkstyle、ArchUnit、JaCoCo 与 Spring Boot repackage 全绿；
- `OpenApiDocumentIntegrationTest` 校验文档版本与核心路径；
- 浏览器与 CLI 的 M12–M14 验收记录见各里程碑文档；
- Docker 镜像构建与容器启动由 CI 的 `docker` 作业校验；本机开发环境未安装
  Docker，因此没有本地容器启动记录。

## 已知限制

- v0.2 无鉴权，默认只监听 `127.0.0.1`，不支持公网多用户；
- 单 JVM、单实例；同一会话同一时刻只有一个活跃 run；
- 自动验证为单条命令、单次重试，不支持验证矩阵；
- 插件与 MCP 服务器均在同进程或本机运行，不构成安全沙箱；
- 不提供图片/多模态输入、并行子代理、远程执行与 Redis 事件总线。
