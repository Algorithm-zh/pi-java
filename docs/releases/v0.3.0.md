# v0.3.0 发布说明

> 版本：0.3.0
> 日期：2026-11-06
> 状态：已发布（2026-11-06）；Git tag 与 GitHub Release 已创建

## 亮点

v0.3 把 pi-java 从“单机只读演示”推进到“可登录、可协作、可回溯的本地 coding agent”：
支持图片输入与附件治理，能用仓库地图快速定位代码；Web 与 HTTP API 引入本地账号、
空间成员与租户隔离；决策时间线让人可以看清每一步证据，并回到任意一次运行之前。

## 新增能力

### 图片与多模态输入（M16）

- Web 端可选择、粘贴或拖拽 PNG/JPEG/WebP/GIF，发送前显示缩略图；
- 模型具备视觉能力时以多模态消息送出，不具备时前后端都会拦下并提示；
- 大图在浏览器内先缩放到 1568 px 并转 WebP，减少请求体与上下文成本；
- 图片历史在会话中保留缩略图与原图入口，SSE 与历史投影使用同一套内容块。

### 附件生命周期与压缩（M17）

- 服务端按内容去重，剥离 EXIF/XMP 等元数据，仅保留渲染所需的字节；
- 默认 512 MB 总配额，超出返回 `ATTACHMENT_QUOTA_EXCEEDED`；
- 每日 03:40 回收无人引用且超过宽限期的附件，设置页展示用量并支持手动清理；
- 上传前压缩只在 Web 入口生效，CLI 仍只支持文本。

### 仓库地图与代码检索（M18）

- 新增内置 `repo_map` 工具：语言分布、目录结构、关键文件与符号索引；
- 按任务关键词做 BM25 风格排序，返回相关文件、符号与匹配行；
- 索引只用 JDK、在进程内存中增量维护，不执行工作区代码；
- 忽略隐藏目录与常见构建目录，超大仓库在 5,000 文件 / 32 MB 处截断并标记。

### 账号、登录与租户隔离（M19）

- 首次启动在 Web 创建管理员，之后使用账号密码登录；
- 浏览器使用 HttpOnly + SameSite=Strict Cookie，脚本与第三方客户端使用
  `Authorization: Bearer`；登录失败有限流，密码只存 PBKDF2 哈希；
- 除公开端点外所有 `/api/**` 都需要登录；会话、工具策略、审批、附件与运行按
  空间隔离；
- 公开就绪探测统一为 `GET /api/v1/auth/state`，容器健康检查同步调整。

### 空间协作（M20–M21）

- 注册即有个人空间；任意用户可创建团队空间，并按登录名邀请已有账号；
- 一个账号可加入多个空间，登录时服务端自动定位、必要时点选，支持一键切换；
- 空间可软删除与恢复；成员制授权区分管理员与成员；
- 设置中心提供账号、空间、成员与邀请管理。

### 决策时间线与任意检查点回溯（M22）

- 每次运行成为一个决策节点，时间线汇总意图、计划、审批、验证与逐轮改动；
- 可展开证据、预览并回退到任意一次运行之前的检查点，工作区与对话一起退回；
- 回退前做冲突预检，任何冲突整体放弃；文件还原覆盖修改、新增与删除；
- 回退后追加“回溯简报”进入下一轮模型上下文，并可通过只读弹窗查看被放弃的片段；
- 运行开始时固定检查点（`pi.git.pin-checkpoints`），删除会话时清理内部 ref。

## 升级说明

- **数据库**：Flyway 自动执行 V6–V8（租户与账号、空间软删除、空间成员关系）。
  存量会话与工具策略归入 `default` 默认空间，创建首个管理员后即可看到。
- **鉴权**：v0.2 的匿名 API 调用现在会收到 401。公开端点只有
  `/api/v1/auth/state|setup|login|register|logout`；健康检查与脚本就绪探测请使用
  `/api/v1/auth/state`。
- **首次启动**：打开页面创建管理员（登录名 + 至少 8 位密码），随后直接进入默认空间；
  自助注册默认开放，可用 `pi.auth.registration-enabled=false` 关闭。
- **CLI**：仍直接使用默认空间，不需要登录；多空间能力只在 Web 与 Bearer 客户端可用。
- **附件**：落盘到 `${PI_DATA_DIR}/attachments`，与数据库一起备份；配额与回收参数
  见 `pi.attachments.*`。
- **产物命名**：`pi-java-app/target/pi-java-app-0.3.0.jar`；镜像示例为
  `pi-java:0.3.0`。
- **新增配置**：`pi.auth.token-ttl`、`pi.auth.registration-enabled`、
  `pi.attachments.*`、`pi.git.pin-checkpoints`。
- 原有会话、工具、审批、MCP 与 CLI 命令保持兼容，只新增端点与字段。

## 启动方式

本机：

```bash
mvn -q -DskipTests package
java -jar pi-java-app/target/pi-java-app-0.3.0.jar
```

脚本（自动探测 JDK 21，可选注入模型 Key）：

```powershell
.\scripts\start.ps1
```

Docker：

```bash
docker build -t pi-java:0.3.0 .
docker run --rm -p 127.0.0.1:8080:8080 \
  -v "$PWD:/workspace" -v pi-data:/app/data pi-java:0.3.0
```

Compose：

```bash
docker compose up --build
```

首次打开 <http://127.0.0.1:8080> 先创建管理员。更多环境变量、MySQL 变体与安全说明
见 [14 部署、容器与 CI](../14-deployment.md)。

## 已知限制

- 单 JVM、单实例：Run 注册表、SSE、审批等待与会话锁都在进程内，不支持横向扩展；
- 模型档案、插件、MCP 服务器与技能目录仍是全局资源，不按空间隔离；
- 没有密码重置、改密、多因素与 SSO；登录限流在进程内，重启清零；
- 令牌只有 7 天有效期与登出吊销，没有刷新令牌与设备管理；
- 附件配额是全局总量，不按空间拆分；不支持 PDF、音频、视频；GIF 不压缩；
- `repo_map` 是关键词检索，不做语义向量与跨文件引用，也不提供 LSP 跳转；
- 回溯只支持运行开始前的检查点，不能回到单轮中间；被放弃的对话只能通过简报回读；
- 内部检查点 ref 长期积累，只随会话删除清理；
- 镜像未发布到镜像仓库，没有多架构、SBOM 与签名；
- 公网部署必须置于 HTTPS 反向代理之后，并建议关闭自助注册。
