# M23 设计：分叉对比

> 日期：2026-11-06
> 状态：设计待评审
> 范围：被放弃分支的只读投影、双分支对比、对比 API 与 Web 面板、CLI
> `/timeline` `/compare` `/rewind`

## 1. 背景

M22 让用户能回到任意决策点。回退之后，旧的 entry 不再属于当前分支，但仍完整保留在
会话日志里；时间线只留一条回溯简报，用户看不到“被放弃的那条路”后来做了什么。

这留下三个问题：

- 回退后无法确认旧分支到底改过哪些文件、哪些验证失败过；
- 无法判断新分支是在重复旧分支已经否决或验证失败的做法；
- 旧 entry 只增不减，却没有任何入口读取，审计价值没有兑现。

M23 只做一件事：**把被放弃的分支重新变成一个可读、可对比的对象**。不切回旧分支，
不改工作区，只在数据库里读取已存在的事实。

## 2. 目标

- 对最近一次回退（或指定的回退）生成一份双分支对比：意图、运行、审批、验证、计划、
  文件改动；
- 对比只读会话 entry，不访问磁盘、不调用 LLM、不改变任何状态；
- Web 时间线的 REWIND 节点提供“对比两条分支”入口，桌面双列、移动端上下堆叠；
- CLI 补齐 `/timeline`、`/compare`，并复用 M22 的回退能力提供 `/rewind`；
- 不新增数据库迁移，不改变 entry 格式。

### 非目标

- 不切回被放弃的分支，也不还原旧分支的工作区（写操作，另立里程碑）；
- 不做两个分支之间的逐行 diff；只做路径级文件差异与两边各自的改动统计；
- 不做跨会话（fork 出的子会话）对比；
- 不做旧 entry 的清理、归档或配额；
- 不自动把对比结果写回模型上下文。

## 3. 数据来源

| 事实 | 来源 |
|---|---|
| 回退点 | 当前分支上的 `BRANCH_SUMMARY`，`details.kind = "rewind"` |
| 被放弃分支的叶子 | 该 `BRANCH_SUMMARY.fromEntryId` |
| 被放弃分支 | `SessionEntryStore.loadBranch(sessionId, fromEntryId)` |
| 当前分支 | `SessionEntryStore.loadBranch(sessionId, leafEntryId)` |
| 分叉点 | 两条分支从根开始的最后一个相同 entry id |
| 运行 | `GIT_CHECKPOINT`（run 边界）、`RUN_SUMMARY`（停止原因/轮数/工具数） |
| 审批 | `APPROVAL`，拒绝按 `decision = DENIED` 判定 |
| 验证 | `VERIFICATION`，失败按 `passed = false` 判定 |
| 计划 | `PLAN` 的整份快照，取段内最后一份 |
| 文件 | `GIT_CHANGES` 的 `files` 列表与行数 |

分叉点由两条分支的实际 entry id 求交集得出，不依赖简报的 `details`，避免历史数据
字段缺失时算错。

## 4. 投影规则

### 4.1 选段

- 被放弃段：分叉点之后到 `fromEntryId`；
- 当前段：分叉点之后到当前叶子，**包含**回退简报本身，但统计时忽略该 entry；
- 分叉点之前的共同历史不计入任一侧。

### 4.2 每侧都计算

| 字段 | 规则 | 上限 |
|---|---|---|
| `intents` | 段内用户消息文本，按顺序 | 20 条，每条 400 字 |
| `runs` | 段内 `GIT_CHECKPOINT` 数 | — |
| `completedRuns` | 段内匹配的 `RUN_SUMMARY` 数 | — |
| `turns` / `toolCalls` | `RUN_SUMMARY` 求和 | — |
| `stopReasons` | 去重后的停止原因，按出现顺序 | 10 条 |
| `approvals` | 总数、拒绝数、被拒工具名 | 工具名 10 条 |
| `verifications` | 总数、失败数、失败命令 | 命令 10 条 |
| `plan` | 最后一份计划的总数、完成数、未完成条目 | 条目 10 条 |
| `changes` | 有改动的轮数、不同文件数、新增/删除行 | — |
| `files` | 段内出现过的路径，合并重复路径并累计行数 | 100 条 |

### 4.3 文件差异

- `onlyAbandoned`：只在被放弃段改过；
- `onlyCurrent`：只在当前段改过；
- `both`：两边都改过；
- 三个列表都按路径排序，各 100 条上限；超出时 `truncated = true`。

### 4.4 摘要

服务端生成确定性中文摘要，不调用 LLM，最多 500 字，例如：

```text
旧分支：2 轮对话、2 个 run、1 次拒绝、1 次验证失败，改过 3 个文件（+40 −12）。
当前分支：1 轮对话、1 个 run，没有文件改动。旧分支独有的文件：a.java、b.java。
```

### 4.5 空与退化

- 会话没有回退 → `available = false`，两侧为空，不报错；
- 回退发生在第一轮之前（被放弃段为空）→ 仍可用，旧侧为空侧；
- 回退后还没有新对话 → 当前侧为空侧；
- 当前分支后续又发生多次回退 → 默认取最近一次的简报；也可指定某一条；
- 指定的简报不在当前分支上 → `INVALID_BRANCH`（HTTP 409）。

## 5. API

```http
GET /api/v1/sessions/{id}/comparison
GET /api/v1/sessions/{id}/comparison?rewind={briefEntryId}
```

响应（省略空值）：

```json
{
  "available": true,
  "rewindEntryId": "01J...",
  "forkEntryId": "01J...",
  "at": "2026-11-06T13:20:00Z",
  "abandoned": { "leafEntryId": "01J...", "intents": [], "runs": 2, "...": "..." },
  "current": { "leafEntryId": "01J...", "intents": [], "runs": 1, "...": "..." },
  "files": { "onlyAbandoned": [], "onlyCurrent": [], "both": [], "truncated": false },
  "summary": "旧分支：…"
}
```

每侧的字段与 4.2 一一对应。所有路径与文本都是服务端已截断的值，前端不再二次
推断分支关系。

## 6. Web

- 时间线里的 REWIND 节点增加次按钮“对比两条分支”；
- 为支持多条回退分别对比，时间线响应给 REWIND 节点补一个 `rewindEntryId`
  （新增字段，RUN 节点为 null，不影响既有字段）；
- 点击后用该 `rewindEntryId` 请求对比，打开与回退预览同级的对话框；
- 顶部一行摘要；主体两列：
  - 左列“被放弃的分支”，右列“当前分支”；
  - 每列依次是意图、运行、关键决定（拒绝的审批、失败的验证、未完成待办）、文件；
- 对话框底部是文件差异分组：仅旧分支 / 仅新分支 / 两边都改过；
- 空侧显示“没有后续动作”，不与另一侧抢高度；
- 移动端两列改为上下堆叠，摘要与文件差异保持可见；
- 全部用 `textContent` 与 DOM 构造，不使用 `innerHTML`；
- 只读对话框，不提供“切回旧分支”按钮。

## 7. CLI

| 命令 | 行为 |
|---|---|
| `/timeline` | 按顺序列出节点：序号、时间、类型、意图或简报首句、统计；标记当前节点 |
| `/compare [n]` | 不带参数时对比最近一次回退；带序号时对比该序号对应的 REWIND 节点 |
| `/rewind <n>` | 先预览简报、将还原的文件与冲突；确认后执行，回车或 EOF 视为取消 |

`/rewind` 复用 `SessionRewindService`，不新增写路径；`/timeline` 与 `/compare` 只读。
行模式从标准输入确认；TUI 需要复用同一个 JLine `LineReader`，因此
`CliTerminal.forTui` 增加一个读取函数参数，默认实现不变。帮助文本、Tab 补全与
提示同步更新。

## 8. 一致性与边界

- 对比不要求会话空闲，也不要求工作区可用；归档会话仍可查看；
- 读取过程中不追加 entry、不推进 leaf、不访问 Git；
- 多个回退嵌套时，对比只看相邻两段，不递归展开更早的分支；
- 列表截断与摘要长度都在服务端完成，避免响应体随历史无限增长。

## 10. 风险

| 风险 | 缓解 |
|---|---|
| 旧分支 entry 很多，响应过大 | 所有列表服务端截断；摘要限 500 字 |
| 分叉点计算错误导致串段 | 用 entry id 交集，不信任简报 details；单测覆盖空侧与嵌套回退 |
| 回退后当前侧包含简报造成计数偏差 | 统计时显式跳过 `BRANCH_SUMMARY` |
| CLI `/rewind` 误操作 | 强制预览 + 确认；非交互直接拒绝 |
| 与 M22 时间线口径不一致 | 复用相同的拒绝/失败判定与截断口径，单测对齐 |

## 11. 验收

- 无回退时 `available=false`，时间线不出现对比按钮；
- 回退后继续对话，对比两侧的意图、拒绝、验证、文件分类正确；
- 嵌套回退默认取最近一次，显式指定旧简报返回 409；
- Web 桌面与移动端走查通过，控制台无错误；
- CLI `/timeline`、`/compare`、`/rewind` 实测通过，非交互拒绝执行回退；
- `mvn -q verify` 全绿，Checkstyle/ArchUnit 与覆盖率门槛通过。
