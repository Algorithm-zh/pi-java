# M1：会话领域与持久化

> 日期：2026-10-21
> 状态：已完成
> 提交：`feat(session): tree session log and context projection`

## 目标

让“会话日志是唯一事实源”从文档变成可运行、可测试的代码：

- 领域层能独立表达会话树、entry、消息与投影规则；
- 持久化层用 Flyway + MyBatis 落实 V1 两表；
- 应用层提供创建、追加消息、分支回退、fork 与上下文投影用例；
- 不接 LLM、不接 Web，为 M4 的 Agent Loop 准备稳定的数据基础。

## 交付物

### 共享内核 `domain.shared`

- `Ulid`：26 位 Crockford Base32，时间有序、可解析、可比较；
- `IdGenerator`：标识生成端口，生产实现基于 ULID；
- `DomainErrorCode` / `DomainException`：稳定错误码与中文可读消息；
- `Guard`：非空、非空白、长度、范围等断言，统一抛领域异常。

### 会话领域 `domain.session`

按职责拆分为 `model`、`model.message`、`model.payload`、`service`、`port`：

| 类型 | 说明 |
|---|---|
| `ChatSession` | 聚合根；只保存身份、标题、配置、状态、leaf 与乐观锁版本 |
| `SessionEntry` | 不可变 entry；校验 seq、parent、payload 类型匹配 |
| `SessionIdentity` | parent/root/fork 起点/depth/origin，支持父会话删除后的孤儿态 |
| `SessionConfig` | cwd、模型档案、思考级别、沙箱快照 |
| `AgentMessage` | sealed：`UserMessage`、`AssistantMessage`、`ToolResultMessage`、`CompactionSummaryMessage`、`BranchSummaryMessage` |
| `ContentBlock` | sealed：`TextBlock`、`ThinkingBlock`、`ToolCallBlock` |
| `EntryPayload` | sealed：10 种 entry 载荷 |
| `SessionContextProjector` | 纯函数：leaf → 祖先链 → 压缩/分支摘要 → 校验工具配对 |
| `SessionBranchPolicy` | 分支目标必须属于本会话，且不能是 toolResult |

关键行为：

- `ChatSession.moveLeaf` 只移动指针，不复制历史；
- `createChild` 基于父会话生成 `FORK` 或 `SUBAGENT` 身份；
- 状态机限制：只有 `IDLE` 会话可以追加消息、移动分支、fork 或切换模型。

### 应用层 `application.session`

- `CreateSessionCommand` / `AppendUserMessageCommand` / `MoveBranchCommand` / `ForkSessionCommand`；
- `SessionApplicationService`：
  - 创建用户会话；
  - 追加用户消息（`seq = count + 1`，先 append entry，再 CAS 更新 leaf）；
  - 分支回退；
  - fork 子会话并写入初始 `BRANCH_SUMMARY` 占位 entry；
  - 按当前或指定 leaf 投影上下文。

事务边界在用例层；每个方法都是短事务。M4 才引入进程内单写者锁，
当前依赖数据库 `(session_id, seq)` 唯一键与 `version` CAS 兜底。

### 持久化 `infrastructure.persistence`

- `SessionPO` / `SessionEntryPO` 与领域对象分离；
- `SessionMapper` / `SessionEntryMapper`：注解 SQL，更新带 `version = version + 1`；
- `MyBatisSessionRepository`：CAS 失败抛 `CONCURRENT_MODIFICATION`；
- `MyBatisSessionEntryStore`：一次加载会话 entry，按 parent 回溯目标分支；
- `EntryPayloadCodec` / `MessageCodec` / `ContentBlockCodec` / `SandboxJsonCodec`：
  - 按 `EntryType` 解码；
  - 时间统一 ISO-8601；
  - 未知 payload 版本抛 `UNSUPPORTED_PAYLOAD`；
  - 脏 JSON 抛 `INVALID_ENTRY`。

### 数据库

- `V1__session.sql`（MySQL 8 / H2 两份）：
  - `pi_session`：元数据、父子会话、leaf、version；
  - `pi_session_entry`：append-only 日志，唯一键 `(session_id, seq)`；
  - entry 随 session 级联删除；父会话删除时子会话 `parent_session_id` 置空。

## 关键设计决策

| 决策 | 原因 |
|---|---|
| 聚合不持有 entry 列表 | 避免每次追加都加载整棵树；分支只改 leaf |
| entry append-only | 审计、回放、压缩都依赖不可变历史 |
| `seq` 由 `count + 1` 分配 | entry 只增不删，数量等于最大 seq；单写者 + 唯一键兜底 |
| `version` 乐观锁 | 跨进程写入也不会静默覆盖；更新失败统一报并发冲突 |
| fork 不复制历史 | 子会话通过 `parent/root/forkFromEntryId` 指向父树；避免日志膨胀 |
| fork 先写占位摘要 | M1 不接 LLM；M7 再升级为真实摘要，entry 结构不变 |
| 允许孤儿子会话 | 数据库 `ON DELETE SET NULL` 保留子会话；领域只允许在重建时出现该状态 |
| 时间列存 UTC | 避免时区迁移；Jackson/MyBatis 均使用 `Instant` |
| test profile 用内存 H2 | 集成测试不污染本地文件库；Flyway 与生产使用同一套迁移语义 |

  - infrastructure codec 单测 7；

- JaCoCo 行覆盖率：
  - `pi-java-domain`：**89.4%**；
  - `pi-java-application`：**98.9%**；
  - 两个模块从 M1 起启用 60% 行覆盖门槛，未达标时 `verify` 失败。
- Checkstyle：主代码全部通过（文件 ≤ 300 行、方法 ≤ 50 行、参数 ≤ 6）。

覆盖的关键场景：

- 同一 entry 序列投影结果稳定；压缩摘要 + 尾部保留；工具调用/结果配对；
- 分支回退后旧分支仍保留，`seq` 继续递增；
- fork 生成正确的 parent/root/depth/origin 与初始分支摘要；
- H2 唯一键冲突、`version` CAS 失败、session 删除级联 entry、父会话删除保留子会话；
- 10 种 payload 的 JSON 往返、未来版本拒绝、脏 JSON 拒绝、中文 UTF-8 往返；
- 相对路径、非法标题、空消息等领域校验。

## 已知限制

- 没有 REST/CLI，应用服务只能由测试或后续模块调用；
- 没有运行中会话锁；`seq = count + 1` 假设单写者，M4 接入 `SessionLockRegistry`；
- fork 的 `BRANCH_SUMMARY` 是占位文本，真实 LLM 摘要在 M7；
- 子会话孤儿态可被加载，但尚未在 UI 表达“父会话已删除”；
- MySQL 真实实例只做了方言审查，本机 smoke 在 M9；
- `MyBatisSessionEntryStore.loadBranch` 当前加载整会话 entry，规模增大后改为递归 CTE。
