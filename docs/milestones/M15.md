> 日期：2026-10-26

## 目标

让项目从“本机可跑”变成“别人拿到仓库也能跑”：

- 接口契约由代码生成，随时可在浏览器里查看与调试；
- 一条命令构建镜像，Compose 起停，数据与用户工作区分开；
- CI 在每次 push/PR 上执行完整质量门禁，并验证容器与 MySQL 链路；
- 版本号、启动脚本、文档与发布说明统一到 `0.2.0`。

## 关键设计

- **容器内监听、宿主侧收口**：镜像默认 `PI_SERVER_ADDRESS=0.0.0.0` 才能在容器内
  被访问，但 Compose 只映射 `127.0.0.1:8080`，宿主机之外仍不可达；v0.2 无鉴权，
  这条边界不能省。
- **数据卷与工作区分开**：H2 文件落 `/app/data` 命名卷，用户仓库挂 `/workspace`；
  升级或删除容器不会带走数据，也不会把数据库文件写进用户项目。
- **契约不手写**：OpenAPI 由 Controller 扫描生成，测试锁定版本与核心路径；接口
  变动会直接让测试失败，避免文档与实现各说一套。
- **CI 与本地同一条命令**：CI 执行 `mvn verify`，不跳过 Checkstyle、ArchUnit 或
  覆盖率；容器作业只负责证明镜像能起、能响应、UI 能打开。
- **MySQL 作业叠加 demo profile**：`demo` 提供离线 `fake-demo` 模型种子，`mysql`
  在后覆盖数据源；冒烟请求显式带上 `modelProfileId`，与真实使用路径一致。
- **镜像不打包测试产物**：构建阶段先 `dependency:go-offline` 再复制源码，
  `-Dmaven.test.skip=true` 只影响镜像构建，不影响 CI 的完整测试。

## 验证

### 构建与测试

```bash
mvn -q verify
```

在项目副本（`%TEMP%/pi-m15-verify/pi-java`）执行，避免覆盖正在运行的 8080 实例：

- 9 个模块全部 `BUILD SUCCESS`，耗时约 1 分 52 秒；
- **770 个测试通过**，0 失败 0 错误，2 个符号链接用例条件跳过；
- Checkstyle、ArchUnit、JaCoCo 覆盖率门槛与 Spring Boot repackage 全部通过；
- `OpenApiDocumentIntegrationTest` 2 个用例：`/v3/api-docs` 的标题、`0.2.0`、
  MIT 许可证与 8 个核心路径；`/swagger-ui.html` 302 到
  `/swagger-ui/index.html` 并返回 200。

### 本地运行

在同一副本用隔离参数启动 0.2.0 jar（端口 18082，`PI_DATA_DIR` 指向临时目录）：

- `/api/v1/system/info` 返回 `version=0.2.0` 与临时工作区根目录；
- `/v3/api-docs` 返回 31 个路径，包含 `sessions`、`plan`、`messages/stream`、
  `runs/{runId}/events`、`models`、`tools`、`system/info`；
- `/swagger-ui.html` 跳转后 200，首页标题为 `pi-java · 你的本地编程搭档`；
- 数据目录生成 `pi-java.mv.db` 与 `pi-java.lock.db`，确认 `PI_DATA_DIR` 生效；
- `POST /api/v1/sessions`（带 `modelProfileId=fake-demo`）建会话成功，
  `GET /plan` 返回空计划快照，`GET /sessions?cwd=...` 能读回同一条会话。

### 容器与 CI

- 本机未安装 Docker，镜像构建与容器启动未在本地执行；
- `Dockerfile` 与两个 compose 文件通过结构与 YAML 解析校验；
- CI 的 `docker` 作业负责真实构建、启动、healthcheck 与 API/OpenAPI/UI 冒烟；
- CI 的 `mysql` 作业在 MySQL 8.4 上跑 Flyway 与建会话读回；本地未复现该环境，
  该链路以 CI 结果为准。

## 已知限制

- 镜像尚未发布到任何仓库，也没有多架构构建、SBOM 与签名；
- `v0.2.0` tag 与 GitHub Release 未创建，需要用户确认后执行；
- MySQL 冒烟只在 CI 跑一次，没有 Testcontainers 或本地一键脚本；
- 容器健康检查依赖 `curl`，镜像因此多装了一个运行时包；
- v0.2 仍无鉴权，Compose 只能绑定回环地址，不适合直接暴露到公网。
