# M13：Git 感知与检查点

> 日期：2026-10-25
> 状态：已完成；`mvn -q verify -Dspring-boot.repackage.skip=true` 全绿
> 范围：run 前快照、逐轮 diff、撤销上一轮、提交建议、未跟踪文件；Web 与 CLI 同步展示

## 目标

让代理的修改从“不可见的副作用”变成“可查看、可撤销的一轮变更”：

- run 开始时记录工作区，结束后能算出一轮到底改了什么；
- 用户不满意时，一键把文件和对话一起退回发送消息之前；
- 撤销不能覆盖用户在代理之后做的新改动；
- 未跟踪文件也要看得见、退得掉；
- 任何 Git 故障都不能打断 run。

硬约束：不创建分支、不移动 HEAD、不写用户索引、不自动提交。

## 交付范围

- 配置：`pi.git.enabled / timeout-seconds / max-diff-chars`（`GitSettings`，默认启用）；
- `domain.git`：
  - 模型：`GitSnapshot`、`GitChangeSet`、`FileChange`、`GitChangeKind`、
    `GitConflict`、`GitRestoreResult`；
  - 端口：`WorkspaceGit`（snapshot / changes / restore）；
  - 服务：`CommitMessageSuggester`（纯启发式提交建议）；
- `domain.session`：
  - `EntryType.GIT_CHECKPOINT / GIT_CHANGES`；
  - `GitCheckpointPayload(runId, baseLeafId, baseTreeSha, headSha, branch)`；
  - `GitChangeSetPayload(runId, turn, baseLeafId, baseTreeSha, treeSha, files, diff,
    truncated, suggestedCommit)`；
  - `ChatSession.rewind(EntryId)`：允许退回空会话；
  - `SessionEntryStore.deleteAll(SessionId)`：撤销第一轮时清空日志；
- `application.git`：
  - `GitCheckpointService`：run 开始快照、逐轮 diff、改动查询；
  - `RunGitTracker`：一次 run 内只在内存保存“上一轮终点树”；
  - `GitUndoService`：冲突预检、还原、回退对话；
  - `SessionGitChanges` / `GitUndoResult`；
- `infrastructure.git`：
  - `CliGitWorkspace`：临时索引快照 / `diff-tree` / `checkout-index` 还原；
  - `GitTempIndex`、`GitCommandRunner`、`GitDiffParser`；
  - `DisabledWorkspaceGit`；`GitConfiguration` 按配置选择实现；
- Agent Loop：run 开始快照，每轮工具执行后记录改动并发布 `workspace.changed`；
- HTTP：`GET /sessions/{id}/changes`、`POST /sessions/{id}/undo`；
- Web：对话区“本轮改动”面板，展开文件列表与 diff，撤销二次确认，冲突列表；
- CLI：`/diff`、`/undo`，TUI 增加改动摘要行；`/tree` 可看到 Git entry 摘要；
- 持久化：Git payload 编解码，无需数据库迁移（复用 `pi_session_entry`）。

## 关键设计

- **临时索引，不碰用户索引**：快照与还原都用 `GIT_INDEX_FILE` 指向临时目录，
  `read-tree` + `add -A --ignore-errors` + `write-tree` 得到树对象；不建分支、
  不动 HEAD、不提交。
- **未跟踪文件天然纳入**：`add -A` 把新文件写进临时索引，`.gitignore` 继续生效；
  撤销时删除本轮新增的文件。
- **跨行尾一致**：快照与还原都带 `core.autocrlf=false`，避免 Windows 换行转换
  让对象与工作区字节不一致。
- **逐轮而非每次全量**：本轮起点树就是上一轮终点树，只有树变化时才写 entry，
  避免空记录与重复扫描。
- **失败即降级**：不是仓库、没装 git、命令超时、写 entry 失败都只记日志；
  run 继续，改动面板隐藏或为空。
- **撤销要么全退，要么不动**：先比对每个本轮路径的当前 blob 与本轮结束 blob，
  有冲突就整体放弃（`rewound=false`），不覆盖用户后来的修改。
- **撤销第一轮清空日志**：分支退回空会话后，下一次追加必须是新的根
  （`seq=1`、`parent=null`），旧 entry 不能保留；还原与清理在同一事务内。
- **提交建议不调用 LLM**：只给 `docs/test/ci/build/chore` 这类低风险类型，
  不替用户声称 `feat` 或 `fix`。

## 已知限制

- 树对象没有 ref 指向，`git gc --prune=now` 后旧检查点不可还原；
- 只能撤销最近一次 run，不能回退到更早检查点；
- 重命名按删除 + 新增处理；新增文件删除后空目录可能残留；
- 子模块只作为 gitlink 参与快照，内部内容不还原；
- 大仓库每轮快照有扫描成本；diff 文本按字符数截断；
- 工作区不是仓库或关闭 Git 时没有改动面板，也没有撤销；
- 不自动提交，提交建议只是启发式。
