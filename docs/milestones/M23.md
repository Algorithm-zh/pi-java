# M23：分叉对比

> 日期：2026-11-06
> 状态：已完成；`mvn -q verify` 1012 个测试通过，Checkstyle 通过，Web 与 CLI 走查完成
> 范围：被放弃分支的只读投影、双分支对比、对比 API 与 Web 对话框、CLI `/timeline`
> `/compare` `/rewind`

## 目标

M22 让用户能回到任意决策点，回退后旧 entry 仍完整保留，但时间线只剩一条回溯简报，
用户看不到“被放弃的那条路”后来做了什么，也无法判断新分支是否重复了旧分支已否决或
验证失败的做法。

M23 把被放弃的分支重新变成一个可读、可对比的对象：意图、运行、审批、验证、计划与
文件改动并排展示。全程只读会话 entry，不切回旧分支、不改工作区、不调用 LLM。

## 交付范围

- 应用：
  - `SessionBranchComparison` 双分支投影模型，列表与文本统一截断；
  - `BranchComparisonProjector` 统计单侧事实、求路径级文件差异、生成确定性中文摘要；
  - `SessionBranchComparisonService` 定位回退简报、计算分叉点、分别投影两段；
- 触发层：`GET /api/v1/sessions/{id}/comparison?rewind={entryId}`，
  返回 `available`、`rewindEntryId`、`forkEntryId`、`at`、两侧投影、文件差异与摘要；
  指定不在当前分支上的简报映射为 409 `INVALID_BRANCH`；
- 时间线：`REWIND` 节点新增 `rewindEntryId`，Web 与 CLI 用它打开对应回退的对比；
- Web：
  - 时间线 `REWIND` 节点新增“对比两条分支”按钮，原生 `<dialog>` 展示摘要、
    双列统计、意图与文件差异；
  - 桌面双列、375px 上下堆叠，加载中在框内提示，失败时显示中文错误；
  - 所有服务端文本用 `textContent` 写入；
- CLI：
  - `/timeline` 打印编号节点、当前标记与每个节点的意图/统计；
  - `/compare [序号]` 对比最近一次回退，或指定回退节点；
  - `/rewind <序号>` 复用 M22 的回退能力：先预览、再校验可回退与输入可用、
    确认后执行；回车取消、EOF 取消；
  - `/` 补全加入三个命令；
- 测试：投影与服务单测、控制器 MockMvc、CLI 命令单测、对比集成测试与 OpenAPI 断言。

## 关键设计

- **分叉点由 entry id 前缀求得**：被放弃侧用简报的 `fromEntryId` 载入分支，当前侧用
  会话叶子载入，两者从根开始的最长相同前缀即分叉点；不依赖简报 `details`，历史数据
  字段缺失也不会算错；
- **选段对称**：被放弃段是分叉点之后到 `fromEntryId`；当前段是分叉点之后到当前叶子，
  包含回退简报本身，但简报不参与任何统计；分叉点之前的共同历史不计入任一侧；
- **默认最近一次回退**：当前分支上可能有多条回退简报，省略 `rewind` 取最近一条；
  指定更早的简报时，当前侧覆盖到当前叶子，更晚的回退简报同样不参与统计；
- **只做路径级差异**：`onlyAbandoned`、`onlyCurrent`、`both` 三组路径按字母序输出，
  不生成逐行 diff；行数统计来自各段 `GIT_CHANGES`；
- **截断在服务端**：意图 20 条（每条 400 字）、停止原因/工具名/验证命令/未完成条目
  各 10 条、文件 100 条、摘要 500 字；超出时标记 `truncated`，调用方不再二次推断；
- **对比是只读的**：不要求会话空闲，不追加 entry，不访问磁盘，不调用模型；
  无回退时返回 `available=false`，两侧为空，不报错；
- **CLI 不绕过回退预览**：`/rewind` 先 dry-run 预览，冲突或不可回退时直接停止；
  行模式同样从标准输入确认，无法读取标准输入时拒绝执行并提示手动操作；
  确认只接受 `y`/`yes`，回车视为取消。

### 浏览器走查

在独立实例（端口 8093，独立 `PI_DATA_DIR`，Fake 模型 + 临时 Git 仓库）上：

1. 两次 `/write` 运行后，在时间线面板对第二个节点预览并确认回退；
2. 继续 `/write` 两轮形成新分支，打开 `REWIND` 节点的“对比两条分支”；
3. 对话框显示“旧分支 / 当前分支”两侧统计、意图与文件差异，摘要正确；
4. 1440×960 为双列，375×812 上下堆叠，无横向溢出；控制台无错误，对比请求无 4xx；
5. 截图见 `docs/images/compare.png` 与 `docs/images/compare-mobile.png`。

### CLI 走查

行模式（`chat --plain`，独立 `PI_DATA_DIR` 与临时 Git 仓库）用同步输入驱动：

1. 两次 `/write` 后 `/rewind 2`：先打印预览，直接回车得到“已取消回退”；
2. 再次 `/rewind 2` 并输入 `y`，打印“已回退 · 还原 N 个文件 · 丢弃 …”；
3. 继续两轮 `/write` 后 `/timeline`：4 个节点，`*` 标记当前节点；
4. `/compare`：显示旧分支/当前分支统计、意图与“仅新分支”“两边都改过”；
5. `/compare 1` 提示“第 1 个节点不是回退点”；`/rewind` 提示“请指定要回退的序号”。

## 已知限制

- 不能切回被放弃的分支，也不还原旧分支的工作区；M23 只读对比；
- 不做逐行 diff，也不做跨会话（fork 子会话）对比；
- 没有回退的会话没有可对比对象；对比默认最近一次回退，指定更早的简报时当前侧
  会覆盖后续全部动作；
- 列表与摘要按固定上限截断，完整文件名列表可能需要在 Web 中分批查看；
- 对比结果不自动写回模型上下文，也不会改变下一次运行的计划。
