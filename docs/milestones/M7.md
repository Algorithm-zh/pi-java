# M7：上下文压缩与 Skills

> 日期：2026-10-22
> 状态：已完成
> 提交：`feat(context): structured compaction and skills`

## 目标

让长会话不再因为上下文窗口而中断，同时把“团队知识”以最低成本注入模型：

- 上下文接近窗口时**自动**压缩，provider 报溢出时**强制**压缩并重试一次；
- 压缩结果是可审阅、可测试的**结构化摘要**（目标/约束/进展/决策/下一步/关键上下文），
  而不是一段自由文本；
- 摘要**不收敛**时降级为“只剪枝 + 保留尾部”，绝不进入无限压缩；
- Skills 从文件系统发现，只把 `名称 + 描述` 注入 system prompt，正文按需读取或由
  `/skill:name args` 显式注入；
- system prompt 补齐环境、工具风险、Skills 目录与 `AGENTS.md`；
- 提供手动 `POST /sessions/{id}/compact` 与 `GET /skills`，Fake demo 可离线演示。

## 交付物

### 领域层 `domain.context`

| 类型 | 说明 |
|---|---|

| `CompactionPlanner` / `CompactionPlan` | 切点计算：保留尾部、跳过 toolResult、split-turn |
| `SummarySection` / `SummaryDraft` | 固定六小节的结构化摘要 |
| `CompactionSummaryFormatter` | 渲染 Markdown，超限按“进展→决策→关键上下文→约束”裁剪 |
| `CompactionOutcome` | 收敛判定：不超预算、不超过原文 70%、摘要短于原文 |
| `CompactionPromptBuilder` | 组装压缩请求（独立 user 消息，不依赖函数调用） |
| `SkillDescriptor` / `SkillCatalog` / `SkillPromptFormatter` | 技能目录与 prompt 片段 |
| `SkillFrontmatter` | `SKILL.md` frontmatter 解析（极简 YAML 子集） |
| 端口 `SkillSource` / `WorkspacePromptSource` | 文件系统与工作区文档的抽象 |

不变量：

- **切点绝不落在 toolResult 上**（否则投影器会看到孤立结果）；
- 上下文仍能整体放进保留窗口时**不压缩**（压缩无收益）；
- 摘要 token ≥ 被摘要原文 token 时判定为不收敛，写入但标记 `prunedOnly=true`；
- 一个 run 内自动压缩最多一次，溢出重试最多一次。

## 关键设计决策

1. **token 口径必须唯一**。实现过程中发现 M1 的 `SessionEntryAppender` 按“3 字符 1 token”
   估算，而投影/压缩按“CJK 1 字符 1 token”计算，中文会话被低估约 3 倍，压缩永远不触发。
   M7 统一到 `EntryTokenCounter`，并用测试锁定两者 `≥` 关系。
2. **压缩是优化，失败不阻断对话**。自动压缩抛错时记录日志并继续；只有“溢出后压缩失败”
   才结束 run，并在错误消息里区分“无法压缩”与“压缩后仍失败”。
3. **不收敛就降级，不重试到天荒地老**。摘要比原文还长时写入 `prunedOnly=true` 的
   COMPACTION entry，配合“每 run 一次”上限，保证行为有界。
4. **摘要请求不依赖工具调用**。压缩用一条独立 user 消息完成，任何文本模型都能用；
   摘要不需要 schema、不需要 function calling，插件/工具故障也不影响压缩。
5. **上一轮摘要参与下一轮压缩**。二次压缩时把旧摘要作为“已有摘要”传入，避免信息在
   多轮压缩中逐级丢失。
6. **Skill 只注入目录**。正文进 prompt 会让每个请求都携带全部知识、并使前缀缓存失效；
   因此默认只给 `名称 + 描述 + 路径`，正文按需 `read` 或 `/skill:` 注入。
7. **Skill 缓存双失效**。TTL（5 分钟）+ 根目录 mtime + 文件 `mtime+size`，兼顾“改了要生效”
   与“每次请求都扫盘”的成本；`?refresh=true` 提供手动兜底。
8. **AGENTS.md 只读根目录**。不在父目录链上查找，避免 system prompt 依赖用户机器上
   不确定的上级目录，影响可复现性。
9. **配置错误不阻止启动**。skill 目录不可读、文件过大、frontmatter 不合规都只跳过该条，
   不让一个坏文件导致应用无法启动。
10. **控制文件规模**。实现过程中 Checkstyle 报出 379 行文件与 7–8 个参数的方法，据此拆出
    `TurnStreamer`、`RunSteps`、`SkillInvocationResolver`、`CompactionComponents`、
    `RunRuntimeDependencies`，最终主循环 287 行。

## 实际运行

Java 21，端口 18081，demo profile（Fake LLM + 内存 H2）：

1. `GET /api/v1/skills` 返回 `[]`（未配置目录时为空）；
2. 新建会话后 `POST /sessions/{id}/compact` 返回
   `{"applied":false,...,"message":"未执行压缩：会话还没有任何消息"}`；
3. 发送 `/read README.md`，SSE 顺序为
   `run.started → turn.started → message.started → message.delta → message.completed →
   tool.started → tool.completed → turn.started → … → run.completed`；
4. 再次 `/compact` 返回 `applied=false`，`tokensBefore=2380`，说明提示与统计生效；
5. 启动日志出现 `已加载 1 个 skill 根目录: [C:\Users\...\.pi-java\skills]`。

## 已知限制

- 摘要质量依赖模型；Fake 模型不解析技能正文，`/skill:` 在 demo 下只验证链路；
- 自动压缩每 run 最多一次、溢出重试一次；超长单轮仍可能压缩后继续溢出，此时 run 以失败结束；
- `keepRecentTokens` 与 `reserveTokens` 目前来自内置推导（窗口的 80% / 一半），
  `AgentSettings.Context` 尚未接入预算推导（配置项已声明，下一步消费）；
- Skill 仅支持单层目录与极简 frontmatter，不支持嵌套、数组与多行块；
- AGENTS.md 只读创建工作目录根目录，不支持上游继承与 `.pi-java/AGENTS.md` 变体；
- 压缩摘要不包含图片/附件（v0.1 无多模态）；
- 手动压缩要求会话 IDLE，运行中需要先停止。
