# M20：登录免选空间、自助注册与空间软删除

> 日期：2026-10-29

> 范围：密码优先的跨空间登录定位、登录页自助注册、空间软删除与恢复，以及对应的 Web 交互
>

> 当前行为见 [05 API 与 CLI](../05-api-and-cli.md) 1.2 节。

## 目标

M19 的登录页把“空间短名”当成必填信息，实际使用中暴露出四个问题：

- 普通成员被要求记住空间短名，否则只能进入默认空间；
- 登录页只有登录入口，被邀请的人无法自己创建账号；
- 建错或不再使用的空间无法删除，只能一直留在列表里；
- 删除如果做成硬删除，成员会连历史会话一起失去。

M20 把登录入口改成“账号 + 密码”，空间由系统定位；补上自助注册；空间删除改为
可恢复的软删除，并在删除后立即切断成员访问。

## 交付范围

- 领域 `com.piagent.domain.identity`：
  - `Tenant` 增加 `deletedAt`、`isArchived()`、`archive(Instant)`、`restore()`；
  - `TenantRepository` 增加 `updateDeletion`，`findAllIds` 只返回未归档空间供后台任务使用；
  - `UserRepository` 增加 `findActiveByUsername`：跨未归档空间查同名账号；
  - `AuthTokenRepository` 增加 `revokeAllForTenant`；
  - 新增错误码 `AUTH_TENANT_REQUIRED`、`AUTH_REGISTRATION_DISABLED`、
    `AUTH_SETUP_REQUIRED`、`TENANT_PROTECTED`；
- 应用 `com.piagent.application.identity`：
  - `AccountLocator`：未填空间时跨全部未归档空间查同名账号；填了短名只查该空间，
    已归档空间视为不存在；
  - `AuthApplicationService.login`：先按短名定位候选，再逐个校验密码；只有密码命中
    多个空间时才要求选择，并返回候选列表；
  - `TenantSelectionRequiredException` 与 `TenantChoice`：携带可选的
    `slug`/`name`，由触发层映射成 409 响应体；
  - `AuthApplicationService.register`：在默认空间创建 `MEMBER` 并直接签发令牌；
    关闭开关时返回 403，零账号时返回 409 要求先初始化；
  - `IdentityAdminService.archiveTenant`/`restoreTenant`：默认空间与当前空间不可删除；
    归档时吊销该空间全部令牌；重复归档/恢复保持幂等；
  - `RegisterCommand`：登录名、显示名、密码；
- 基础设施：
  - V7 迁移给 `pi_tenant` 增加可空 `deleted_at`（H2 与 MySQL 各一份）；
  - MyBatis 租户/用户/令牌仓储补齐软删除过滤、按短名查询与按空间吊销；
- 触发层：
  - `POST /api/v1/auth/register`；
  - `DELETE /api/v1/tenants/{id}` 与 `POST /api/v1/tenants/{id}/restore`，均返回 204；
  - 登录请求体保持 `{username, password, tenantSlug?}`，但省略短名时从“默认空间”
    改为跨空间自动定位；409 响应附带 `tenants` 候选；
  - `/api/v1/auth/state` 增加 `registrationEnabled`；
- Web：
  - 登录卡只保留账号、密码；“这个账号同时属于多个空间”时才展开候选按钮，
    并高亮上次进入的空间（`localStorage` 的 `pi-last-tenant`）；
  - 候选区保留“直接填写空间短名”输入框，供脚本或明确知道短名的用户使用；
  - “创建一个”切换到注册卡，显示名可选，密码需二次确认；
  - 设置中心“账号与空间”拆成启用空间与“已删除的空间”；删除需输入空间短名确认，
    删除后对应空间从列表消失并出现在归档区，可一键恢复。

## 关键设计

- **密码优先，空间后置**：服务端先收集同名账号，只有密码真正匹配多个空间时才返回
  409 让用户点选。这样普通用户完全不需要知道短名，同名多空间也不会因为“猜空间”
  而误报密码错误。
- **错误文案不泄漏空间**：候选为空时同样执行一次假哈希校验，保持耗时一致；已归档
  空间不参与定位，成员登录得到与密码错误相同的提示。
- **软删除是访问控制，不是数据清理**：归档只写 `deleted_at` 并吊销令牌，会话、附件、
  策略与审批全部保留；恢复后成员用原密码即可继续使用。
- **保护默认空间与当前空间**：默认空间是系统的兜底租户；当前空间是管理员此刻正在
  使用的入口。两者都不能删除，避免把管理员锁在门外。
- **注册默认落在默认空间**：自助注册不改变租户模型，新账号是默认空间的 `MEMBER`；
  需要独立空间的团队仍由管理员创建空间并分配管理员。
- **记住上次空间只发生在本机**：偏好存浏览器 `localStorage`，不写服务端，不跨设备
  同步，也不影响其他账号的候选排序。

### 浏览器走查

在 8081 起独立实例（`demo` 配置，`PI_DATA_DIR` 指向 `target/m20-data`），
用应用内浏览器完成以下路径：

- 初始化管理员 `boss`；登录页只要求账号与密码；
- 创建空间“团队 B”（管理员 `bob`）与“团队 C”（管理员 `boss`），并用“创建一个”

- `bob` 登录时自动进入“团队 B · 管理员”，不出现空间选择；
- `boss` 登录时出现候选“默认空间 / 团队 C”，上次进入的“默认空间”带高亮；
  候选下方保留短名输入框；
- 在“账号与空间”删除“团队 B”：输入短名 `team-b` 后确认按钮才可用，删除后该空间
  转入“已删除的空间”并显示删除日期；
- `bob` 登出后登录被拒（与密码错误同一提示）；

控制台除登录失败用例预期的 401/409 外没有其他错误；8080 上的既有实例未受影响。

## 已知限制

- 自助注册只能加入默认空间；其他空间仍由管理员在设置中心创建账号；
- 登录名只在空间内唯一，同名账号跨空间由候选点选区分，没有全局账号；
- 没有邮箱验证、忘记密码与改密入口，密码只能由管理员重建账号；
- 空间删除没有保留期与自动清理，归档数据会一直留在数据库中；
- “上次空间”只记录在当前浏览器的 `localStorage`，换浏览器或清缓存后需要重新选择；
- CLI 仍固定绑定默认空间且不登录，多空间能力只在 Web 与 Bearer 客户端可用；
- 模型档案、插件、MCP 与技能目录仍是进程级全局资源。
