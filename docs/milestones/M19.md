# M19：多租户与最小鉴权

> 日期：2026-10-29
> 状态：已完成；`mvn -q test` 923 个测试通过（2 个符号链接用例条件跳过），浏览器走查见“验证”一节
> 范围：本地账号体系、会话令牌、HTTP 鉴权过滤器、租户隔离，以及 Web 登录/初始化界面

## 目标

M18 之前，pi-java 是“监听回环地址的单用户工具”，所有接口都能被本机任意程序调用。
M19 补上最小可用但完整的身份边界，让服务能被多个使用者安全共享：

- 首次启动通过页面创建管理员，之后用账号密码登录，不再依赖“本机即可信”；
- 会话、工具策略、审批、附件与运行按租户隔离，查询与写入都不跨租户；
- 浏览器用 HttpOnly Cookie，命令行与第三方客户端用 Bearer 令牌；
- 只用 JDK 与现有依赖，不引入 Spring Security、OAuth 或外部身份服务。

## 交付范围

- 领域 `com.piagent.domain.identity`：
  - `Tenant`、`TenantId`（默认租户固定 ULID）、`AppUser`、`UserId`、`UserRole`、
    `AppUserStatus`、`AuthToken`、`AuthTokenId`；
  - `TenantRepository`、`UserRepository`、`AuthTokenRepository` 端口；
- 应用 `com.piagent.application.identity`：
  - `AuthContext`：请求线程绑定主体与租户；`callAs`、`callAsTenant`、`wrap`
    在子线程显式传播；无绑定时回退默认租户，只服务进程内任务；
  - `AuthPrincipal`：租户、用户、展示名与角色；
  - `AuthApplicationService`：初始化、登录、令牌校验、登出、当前账号；
  - `IdentityAdminService`：租户列表/创建、当前租户账号列表/创建，全部要求管理员；
  - `LoginThrottle`：同一 `租户|用户名` 15 分钟窗口内 5 次失败锁定 5 分钟；
  - `UserProvisioner`：用户名小写规范化、密码长度 8–128、PBKDF2 编码；
  - `TenantTaskRunner`：启动恢复、标题回填与附件回收按租户逐个执行；
- 基础设施：
  - `Pbkdf2PasswordHasher`（PBKDF2WithHmacSHA256，210,000 次迭代，随机盐）；
  - `Sha256TokenCodec`（43 字符 URL-safe 令牌，落库只有 64 位小写十六进制哈希）；
  - MyBatis 租户/用户/令牌仓储；V6 迁移新增三张表并给会话、策略补 `tenant_id`；
  - 会话、工具策略、审批、附件存储与 run 查询在仓储层追加当前租户条件；
- 触发层：
  - `AuthFilter`：除状态、初始化、登录、登出外，所有 `/api/**` 必须携带有效令牌；
    校验通过绑定主体，请求结束清理线程上下文；
  - `AuthController`：`/state`、`/setup`、`/login`、`/logout`、`/me`；
  - `IdentityAdminController`：`/api/v1/tenants`、`/api/v1/users`；
  - `AuthCookies`：`pi_session`，HttpOnly、SameSite=Strict、7 天；
  - CLI 与启动任务绑定默认租户，保持单机命令行用法不变；
- Web：登录/初始化门禁、账号信息卡、设置中心“账号与空间”、会话过期回到登录页。

## 关键设计

- **两种载体、一个令牌**：浏览器走 Cookie，脚本走 `Authorization: Bearer`；两者校验
  同一张 `pi_auth_token` 表，登出即吊销，不存在只对浏览器有效的会话。
- **令牌只存哈希**：数据库泄漏时拿到的是 SHA-256 摘要，无法直接回放；令牌明文只在
  登录/初始化响应出现一次。
- **密码不落明文、错误不区分账号**：PBKDF2 编码带迭代次数与盐；未知租户、未知用户、
  已停用、密码错误统一返回 `AUTH_INVALID_CREDENTIALS`，并按同样成本做一次哈希校验，
  避免通过耗时与文案枚举账号。
- **状态接口自行校验令牌**：`/api/v1/auth/state` 是公开接口，不经过过滤器，所以控制器
  自己解析 Cookie/Bearer 再返回 `authenticated`；否则页面刷新后会误判为未登录。
- **隔离在仓储层兜底**：控制器与服务不手写租户过滤；仓储统一从 `AuthContext` 取租户
  追加到 SQL 或文件路径。跨租户 id 查询表现为“不存在”，避免泄漏资源是否存在。
- **默认租户平滑升级**：V6 用固定 ULID 建 `default` 租户，存量会话与策略自动归入；
  升级后首次打开页面要求创建管理员，旧数据仍可见。
- **角色只分两级**：`ADMIN` 可管理租户与账号，`MEMBER` 只能使用自己的工作区；
  不在本里程碑引入细粒度权限模型。

## 已知限制

- 模型档案、插件、MCP 服务与技能目录仍是全局资源，不按租户隔离；租户隔离范围是
  会话、工具策略、审批、附件与运行；
- 没有密码重置、改密、多因素与 SSO；忘记密码只能由管理员重建账号；
- 登录失败计数保存在进程内，重启后清零，多实例部署不共享；
- 令牌只有 7 天有效期与登出吊销，没有刷新令牌与设备管理；
- CLI 不做登录，固定绑定默认租户，适合单机自用；多人共用应使用 Web 或 Bearer 客户端；
- 附件目录与数据库仍由单进程管理，跨租户配额是总额限制而非按租户配额。
