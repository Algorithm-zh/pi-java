# M2：模型接入与流式 LLM Gateway

> 日期：2026-10-21
> 状态：已完成
> 提交：`feat(model): model profiles and streaming llm gateway`

## 目标

在 M1 的会话日志之上接入模型，但仍不启动 Agent Loop：

- 领域层能表达模型档案、能力约束与流式调用契约；
- 持久化层用 V2 表保存模型档案，密钥只存环境变量名；
- 应用层提供档案 CRUD 与启停用例，版本冲突用 CAS 拒绝；
- 基础设施提供 Fake 与 OpenAI-compatible 两个 provider，离线可测全部流式语义；
- 触发层提供 `/api/v1/models`，为 M4 的会话运行时准备配置入口。

## 交付物

### 模型领域 `domain.model`

| 类型 | 说明 |
|---|---|
| `ModelProfile` | 聚合根：身份、展示名、`ModelEndpoint`、启用状态、版本 |
| `ModelEndpoint` | provider、baseUrl、apiKeyEnv、模型名、上下文/输出上限、能力 |
| `ModelId` | 小写稳定 key，最长 64 |
| `ProviderType` | `OPENAI_COMPATIBLE / ANTHROPIC / FAKE` |
| `ModelRef` | provider + 模型名，真正发给 provider 的标识 |
| `ModelCapabilities` | streaming / toolCalls / thinking |
| `Usage` | input / output / cacheRead / cacheWrite / totalTokens |
| `ModelSelectionPolicy` | 启用校验与能力校验，禁止静默降级 |

档案编辑（`rename/updateEndpoint/enable/disable`）保留原版本；仓储以旧版本做 CAS，
成功后应用层调用 `withVersion`。`withVersion` 禁止版本回退，防止重放旧对象覆盖新状态。

密钥安全由构造约束兜底：`apiKeyEnv` 只接受 `[A-Z][A-Z0-9_]{0,127}`，
`FAKE` 之外的 provider 必须有 http(s) `baseUrl`；`maxOutputTokens <= contextWindow`。

### 流式端口 `domain.model.llm`

- `LlmGateway.stream(LlmRequest, LlmCallContext)`；
- `LlmStream extends Iterator<LlmDelta>, AutoCloseable`：惰性连接、`DoneDelta` 收尾、
  `response()`、`cancel()`、`isCancelled()`；
- `LlmDelta` sealed：`TextDelta / ThinkingDelta / ToolCallDelta / DoneDelta`；
- `LlmRequest(profile, systemPrompt, messages, tools, thinkingLevel)` 复用会话消息类型，
  不维护第二套消息层次；
- `LlmResponse`：最终内容块、`Usage`、`AssistantStopReason`、错误信息；
- `LlmErrorCode`：可重试与不可重试错误分离；`LlmGatewayException.retryable()` 统一判定。

### 应用层 `application.model`

- `CreateModelProfileCommand` / `UpdateModelProfileCommand`；
- `ModelProfileApplicationService`：create / update / enable / disable / find / listAll /
  listEnabled / requireEnabled；
- 重复创建抛 `MODEL_ALREADY_EXISTS`；启停幂等；更新后返回 `withVersion(old + 1)`；
- 8 个内存端口单测覆盖主路径、重复、缺失、幂等与停用拒绝。

### 持久化 `infrastructure.persistence.model`

- `ModelProfilePO`、`ModelProfileMapper`、`ModelProfilePoConverter`、
  `MyBatisModelProfileRepository`、`ModelCapabilitiesCodec`；
- `UPDATE ... WHERE id = #{id} AND version = #{version}`，影响行数为 0 时抛
  `CONCURRENT_MODIFICATION`；更新语句同时 `version = version + 1`；
- `capabilities_json` 缺失字段按 false 处理；非对象或脏 JSON 抛 `INVALID_ARGUMENT`；
- `V2__model_profile.sql`（MySQL / H2 两份）已加入 Flyway。

### LLM 适配器 `infrastructure.llm`

```text
infrastructure.llm
├── LlmModelProvider         provider 级 SPI：supports + stream
├── RoutingLlmGateway        provider -> 实现的 EnumMap 路由
├── fake/                    FakeLlmProvider、FakeTurn
└── openai/                  请求映射、SSE 解析、错误映射、事件流、provider
```

Fake：

- `FakeTurn.text / toolCall / partialThenFailure / failure / echo`；
- 工具参数 JSON 被拆成两个片段，验证增量合并；
- 失败只能发生在全部脚本 delta 之后；
- 脚本耗尽自动回声，demo 无需配置密钥；
- 取消会中断 25ms 分块输出，关闭幂等。

OpenAI-compatible：

- JDK 21 `HttpClient` + Jackson，不引入 Spring AI；
- 请求映射：system/用户/assistant/tool/压缩与分支摘要，工具 schema 解析；
- SSE 解析：`data:`、`[DONE]`、文本、`reasoning_content`、分片 `tool_calls`、usage；
- 错误映射：401/403、408、429、5xx、400 上下文溢出、其他 400；
- 连接惰性；429/5xx/408/网络在首个 delta 前最多重试 2 次；输出开始后不重试；
- 总超时覆盖建连与读取；取消关闭响应体；`MISSING_API_KEY` 不发请求。

### 触发层 `trigger.http.model`

- `GET /api/v1/models`、`GET /api/v1/models/{id}`；
- `POST /api/v1/models`、`PUT /api/v1/models/{id}`；
- `POST /api/v1/models/{id}/enable|disable`；
- DTO 与领域对象分离；未知 provider、缺 capabilities、非法 JSON 统一 400；
- `ApiExceptionHandler`：NOT_FOUND → 404，冲突/停用 → 409，其余领域错误 → 400；
- 响应只出现 `apiKeyEnv`，不出现任何密钥值。

## 关键设计决策

1. **endpoint 是值对象**：把 provider/URL/密钥变量/窗口/能力聚合，避免聚合与 API、DDL
   各散落一套字段；也方便 M4 在 run 开始时冻结模型快照。
2. **消息复用会话模型**：`LlmRequest` 直接使用 `AgentMessage`，provider 适配器负责翻译；
   代价是模型端口知道会话类型，收益是没有第二套消息体系与映射漂移。
3. **端口是 Iterator 而不是回调**：调用方用 `while (hasNext())` 拉取，天然支持取消、
   背压与虚拟线程；adapter 内部不用锁，也不用额外线程池。
4. **重试只发生在 adapter 打开阶段**：一旦有 delta 输出，重试会造成重复文本或工具调用；
   因此重试与“是否已输出”绑定，而不是与 HTTP 状态码单独绑定。
5. **版本由应用层推进**：领域记录不自我递增版本；仓储 CAS 成功后由应用层
   `withVersion(old + 1)` 返回，避免领域对象假装知道数据库状态。
6. **Fake 是产品的一部分**：demo、E2E、后续 SSE 演示都依赖确定性输出；它不是测试补丁。

`mvn -q verify` 全绿：

| 模块 | 测试数 | 覆盖内容 |

| domain | 52 | 档案约束、CAS 版本语义、选择策略、LLM 契约 |
| application | 18 | 模型档案用例、会话用例、内存端口 |
| infrastructure | 46 | Fake、路由、请求映射、SSE 解析、WireMock 全链路、codec |

覆盖率：domain 85.4%、application 98.3%（门槛 60%）。

实际运行（demo profile，H2 文件库 + Flyway V1/V2）：

- `POST /api/v1/models` 创建 Fake 与 DeepSeek 档案；
- `GET /api/v1/models` 返回两个档案，只有 `apiKeyEnv`，无密钥；
- `POST .../disable` → `version=2`，`enable` → `version=3`，`PUT` → `version=4`；
- 重复创建/非法请求 400，不存在 404；
- 启动日志确认 Flyway 应用 V2，H2 文件库持久化。

## 已知限制

- 未用真实 DeepSeek Key 做联网调用：本机未配置密钥，且 M2 没有 Agent Loop；
  真实模型验收安排在 M9（需要用户提供环境变量）。
- 未处理 Anthropic 原生协议；`ProviderType.ANTHROPIC` 目前只用于建模与拒绝。
- `thinkingLevel` 尚未翻译为 provider 参数，等真实模型支持后再加，避免发送无效字段。
- 模型选择策略只做启用/能力校验；“未指定时选默认模型”留给 M4 的 run 创建用例。
- 重试退避是短固定步长，不是指数退避；单机 demo 场景足够，多实例/高并发留给后续。
