# M25：分支切回

> 日期：2026-11-07
> 状态：已完成；`mvn -q verify` 976 个测试通过，Checkstyle 通过，Web 与 CLI 走查完成
> 范围：树证据与分支树保活、切回用例与简报、`/resume` API、时间线 `RESUME` 节点、
> 双向对比、Web 与 CLI 切回入口

## 目标

M22 让用户能回到任意检查点，M23 让被放弃的分支可读、可对比，但两条路仍然只有一条
能继续：想回到旧分支只能重新回退，而回退点之后的新分支会被再次放弃。用户真正需要的是
“在两条已走过的路之间来回切换”，并且对话上下文与工作区一起还原。

M25 把回溯简报变成可逆的切换点：从任意回溯或切回节点出发，移动到另一条已知分支的
叶子，追加切回简报，并还原那条分支的工作区。切换只在同一会话内移动叶子，不合并、
不复制 entry、不移动 HEAD。

## 交付范围

- 领域与应用：
  - `BranchTrees` 从分支 entry 回溯工作区树证据，优先级为
    `GIT_CHANGES.treeSha` → 检查点 `baseTreeSha` → 简报 `toTreeSha`；
  - `RewindBriefBuilder` 与 `BranchSummaryPayload.details` 增加 `fromTreeSha` /
    `toTreeSha`，回溯也记录还原前后的树；
  - `SessionBranchResumeService` 校验空闲状态、定位目标叶子、计算两侧尾段与树、
    预览还原计划、执行叶子移动 + 简报 + 工作区还原；
  - `BranchResumeBriefBuilder` 生成确定性切换简报，包含两侧对话/run 数、改动文件、
    目标意图、应避免重复的审批与验证、用户备注；
  - `SessionTimelineService` 输出 `RESUME` 节点与 `branchEntryId`，分支节点统一读取
    `leftEntries` / `leftRuns`（兼容旧 `discardedEntries` / `discardedRuns`）；
  - `SessionBranchComparisonService` 同时接受回溯与切回简报，摘要使用“另一条分支 /
    当前分支”中性措辞；
- 触发层：`POST /api/v1/sessions/{id}/resume`，请求 `{branchEntryId, dryRun, note}`；
  返回 `switched`、`available`、`restorable`、`unavailableReason`、`targetLeafId`、
  `files`、`restored`、`conflicts`、`briefEntryId`、两侧 entry/run 数与简报；
  对比接口接受 `?branch=`（保留 `rewind` 别名）；
- Git：确认后先实时快照当前树，再移动叶子、追加简报、还原工作区；两侧叶子用
  `refs/pi/checkpoints/<sessionId>/branch-<leaf>` 保活；
- Web：
  - 回溯与切回节点新增“切回这条分支”，原生 `<dialog>` 先预览文件、两侧数量与备注；
  - 切回后聊天区追加“切回简报”卡片，可查看离开的片段，也可直接打开对比；
  - 对比对话框的“旧分支 / 当前分支”改为“另一条分支 / 当前分支”，同时服务两种节点；
- CLI：`/resume [序号]` 先 dry-run 预览，再确认执行；目标不可用时不询问确认；
  非交互终端拒绝切换；`/timeline` 标注“回溯”与“切回”，`/compare` 接受两种节点；
- 测试：树证据、简报生成、切回服务、控制器 MockMvc、时间线与对比投影、CLI 命令、
  OpenAPI 路径断言，以及真实服务中的双向往返集成测试。

## 关键设计

- **切换点是简报本身**：回溯简报的 `fromEntryId` 是离开时的旧叶子，切回后从那里继续；
  新切回简报的 `fromEntryId` 是刚离开的叶子，因此同一份简报总能原路返回，不需要额外
  的分支表；
- **目标树优先取简报快照**：`fromTreeSha` 是离开时实时快照，能带回离开前的未记录改动；
  旧简报没有该字段时，沿目标分支找最后一份树证据，仍缺失则 `available=false`；
- **只在两侧树都可用时计算计划**：`planRestore(targetTree, currentTree)` 同时给出文件
  列表与冲突；预览与执行使用同一计划，确认后工作区再变化时整体失败；
- **事务顺序与回溯一致**：写实时树快照 → 移动叶子 → 追加简报 → 还原工作区 → 固定
  两侧树；数据库步骤失败回滚事务且工作区未动，工作区失败回滚事务与简报；
- **不合并、不复制**：叶子移动后旧分支 entry 全部保留，只是不在当前分支上；两条分支
  的文件改动不会叠加，冲突一律整体放弃；
- **简报是确定性文本**：不调用 LLM，不包含文件内容或完整验证输出，摘要最多 400 字，
  备注最多 200 字；
- **可以反复往返**：每次切换都会固定离开与目标两侧的树，因此没有运行检查点的叶子也
  能再次切回或对比。

### CLI 走查

行模式（`chat --plain`，独立 `PI_DATA_DIR` 与临时 Git 仓库）用同步输入驱动：

1. `/timeline` 显示 4 个决策点，回溯与切回节点分别标注“回退”“切回”；
2. `/resume <序号>` 先打印预览：两侧记录/run 数、将改动的文件与简报；
3. 输入 `y` 后打印“已切换 · 改动 N 个文件”，并逐行列出文件；
4. 回车取消时不发第二次请求；非交互终端直接拒绝并提示手动操作；
5. `/compare` 与 `/compare <序号>` 对切回节点输出中性措辞与文件差异。

## 已知限制

- 只支持同一会话内切换，不支持跨会话或 `fork` 子会话；
- 不合并两条分支，也不做工作区三方合并；冲突时整体放弃；
- 逐文件还原中途失败时数据库会回滚，但工作区可能残留部分已写文件，重试通常以冲突
  形式暴露；
- 旧版简报没有工作区树时可能无法切换，需要先在目标分支建立检查点；
- 反复切换会线性增加简报 entry，本里程碑不做清理或配额；
- 对比仍是路径级差异，不做逐行 diff。
