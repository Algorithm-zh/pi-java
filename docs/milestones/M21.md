# M21：个人空间与团队协作

> 日期：2026-11-05
> 状态：已完成；`mvn -o test` 946 个测试通过，Checkstyle 通过，Web 浏览器走查完成
> 范围：全局账号、空间成员关系、个人空间、团队空间创建与邀请、空间切换，以及对应的 Web 交互

## 目标

M20 结束时账号仍归属于唯一空间：自助注册会落进所有人事先共享的默认空间，
一个团队想独立协作只能由管理员另建空间并单独开账号。实际使用中这带来三个问题：

- 每个人修改默认空间，等于修改所有人的数据；
- 新人注册后没有属于自己的空间，只能和其他人混在一起；
- 已有账号无法被邀请进另一个空间，团队协作只能重复建号。

M21 把账号与空间解耦：账号是全局身份，空间通过成员关系加入；注册后先拥有个人
空间，团队空间按需创建，成员按登录名邀请，随时可以切换。

## 交付范围

- 领域 `com.piagent.domain.identity`：
  - `AppUser` 去掉空间与角色，登录名全局规范化且唯一；
  - 新增 `SpaceMember`（空间、账号、角色）与 `MembershipRepository`
    （按账号、按空间查询，`countAdmins`）；
  - 新增 `TenantKind { DEFAULT, PERSONAL, TEAM }`，`Tenant.create` 携带类型，
    并提供 `isDefault()`/`isPersonal()`；
  - `UserRole` 语义改为“空间内角色”；`UserRepository` 提供全局按登录名查询；
- 应用 `com.piagent.application.identity`：
  - `PersonalSpaceService.ensurePersonal`：为账号懒创建个人空间（slug 形如
    `u-<登录名>-<随机后缀>`），已是管理员时幂等返回；
  - `AccountLocator`：用户名 + 可选空间短名 → 按成员关系生成候选；
  - `AuthApplicationService`：登录候选携带空间类型；`switchSpace` 校验成员关系、
    签发新令牌并吊销旧令牌；初始化同时创建默认空间与个人空间；注册直接进入个人空间；
  - `IdentityAdminService`：空间列表按当前账号的成员关系返回（含归档）；任何登录
    用户可创建团队空间并成为管理员；`inviteMember`/`findInvitable` 支持按登录名
    邀请已有账号；`listUsers`/`createUser` 要求当前空间管理员；
  - 归档保护顺序：默认空间 → 个人空间 → 当前空间，全部返回 `TENANT_PROTECTED`；
- 基础设施：
  - V8 迁移新增 `pi_tenant.kind` 与 `pi_space_member`，把存量账号的原空间与角色
    回填为成员关系，再从 `pi_app_user` 删除 `tenant_id`/`role`；
  - 新增 `MyBatisMembershipRepository`、`SpaceMemberMapper/PO`；用户仓储改为全局查询；
- 触发层：
  - `POST /api/v1/auth/switch`，切换后下发新的 `pi_session` Cookie；
  - `POST /api/v1/tenants` 改为 `{slug, name}`，不再创建管理员账号；
  - `GET /api/v1/users/lookup?username=` 与 `POST /api/v1/tenants/{id}/members`；
  - 空间列表返回 `kind` 与当前账号在该空间的 `role`；登录 409 候选带 `kind`；
- Web：
  - “账号与空间”重写为“我的空间”：类型、角色、当前标记，“进入”按钮切换空间；
  - 任何用户可创建团队空间；只有团队空间管理员能看到删除按钮；
  - 成员区拆成“邀请已有账号”和“创建新账号”，前者按登录名查找并选择角色；
  - 登录候选标注空间类型，并按登录名记住该账号在本机上次使用的空间；
  - 点击侧栏账号卡直接打开“账号与空间”。

## 关键设计

- **账号全局、角色按空间**：权限判断只使用当前空间的成员关系。同一账号在个人空间
  是管理员，在被邀请的团队空间里可以是成员，互不影响。
- **注册即个人空间**：自助注册创建 `PERSONAL` 空间并成为其管理员，不再写入共享
  默认空间。升级前的账号保持原有数据在默认空间可见，并在下次登录时懒补个人空间。
- **懒创建而不是批量迁移**：个人空间只在账号真正登录/注册/被创建时生成，迁移脚本
  只回填成员关系，避免升级时给所有存量账号一次性造空间。
- **切换即换令牌**：`/auth/switch` 签发新令牌并吊销旧令牌，旧令牌无法继续访问已离开
  的空间；Cookie 与 Bearer 两种载体行为一致。
- **成员制授权**：空间列表、成员管理、归档与恢复都以成员关系为准；创建空间不要求
  任何全局管理员身份，创建者自然成为该空间管理员。
- **保护不可替代的入口**：默认空间承载升级前数据，个人空间是注册后的落脚点，当前
  空间是正在使用的入口，三者都不能删除。

### 浏览器走查

在隔离实例（`--server.port=8081`，独立 `PI_DATA_DIR`，不触碰用户 8080 服务）上用
浏览器完整走了一遍：

1. 初始化管理员 `boss` 后，侧栏账号卡显示“默认空间 · 管理员”；点击账号卡直接
   打开设置中心“账号与空间”，无需再从设置按钮进入；
2. “我的空间”列出默认空间（当前）与自动生成的“Boss 的空间”（个人空间 · 管理员），
   个人空间行只有“进入”；切换后侧栏变为“Boss 的空间 · 管理员”，会话列表随之清空，
   确认数据按空间隔离；
3. 创建团队空间“设计组”（`design`）后，列表出现“团队空间 · design · 管理员”，
   当前空间行没有删除按钮，非当前团队空间才有“删除”；
4. 自助注册 `lily` 直接进入“小鹿 的空间（个人空间 · 管理员）”，空间列表里看不到
   默认空间或他人的空间，确认新账号不再落进共享默认空间；
5. `boss` 在“设计组”按登录名查找 `lily` 并邀请为成员；`lily` 再登录时空间候选
   列出“设计组（团队空间）”和个人空间，进入设计组后侧栏显示“设计组 · 成员”，
   且该行只有“进入”、没有“删除”，角色权限符合预期；
6. `boss` 切回个人空间后删除“设计组”，出现“已删除的空间”与“恢复”；恢复后空间
   重新出现在列表中，成员可继续进入；
7. 登录自动定位：`boss` 退出后只填账号密码即直接回到上次使用的“设计组”，不再弹出
   空间候选。

走查中发现并修复两个问题：

- 上次空间原本只用一个浏览器级键保存，同一浏览器换账号登录会串用别人的记录，
  导致自动回到上次空间失效；改为按登录名保存（`pi-last-tenant:<登录名>`），
  换账号互不影响；
- 当前空间在默认空间时显示成“默认空间（默认空间 · 管理员）”，名称与类型重复；
  类型标签与空间同名时不再重复显示。



- 不能主动退出空间、移除成员或转移空间管理员；
- 邀请直接生效，没有邀请链接或“待接受”状态；
- 空间不能改名，也没有空间级配额与审计日志；
- 个人空间名称与短名自动生成，暂不支持修改展示名；
- 归档不会物理清理数据，也没有保留期；
- CLI 仍固定使用默认空间，多空间能力只在 Web 与 Bearer 客户端可用；
- 模型档案、插件、MCP 与技能目录仍是进程级全局资源。
