# M3：只读工具与路径沙箱

> 日期：2026-10-21
> 状态：已完成
> 提交：`feat(tool): read-only tools and path sandbox`

## 目标

在 M1 会话日志与 M2 模型接入之上，建立可被 Agent Loop 使用的工具目录与安全边界，
但暂不接 LLM 自动调用：

- 领域层能表达工具定义、调用、结果、访问策略与纯路径沙箱；
- 基础设施实现 `read/ls/grep/glob` 四个只读工具，具备超时、截断与二进制保护；
- 持久化 V3 策略表，按工作区/用户解析 `ALLOW / ASK / DENY`；
- 触发层提供 `GET /api/v1/tools`，为 M4 的 Web UI 与 Agent Loop 准备工具视图。

## 交付物

### 工具领域 `domain.tool`

| 类型 | 说明 |
|---|---|
| `ToolName` | 小写开头，允许 `[a-z0-9._-]`，最长 128 |
| `ToolCallId` | LLM 调用 ID |
| `ToolRisk` | `LOW / MEDIUM / HIGH / CRITICAL` |
| `ExecutionMode` | `PARALLEL / SEQUENTIAL` |
| `ToolDescriptor` | 不可变定义：名称、描述、schema、风险、执行模式、超时（≤10 分钟） |
| `ToolInvocation` | 调用 ID、工具名、不可变参数、冻结的 `SandboxPolicy` |
| `ToolResult` | 文本内容、`error` 标志、结构化 `details`；失败不抛异常 |
| `ToolCatalog` | 不可变目录，拒绝重名，`find/require` 统一错误码 |
| `ToolArgumentGuard` | 拒绝未知参数，读取并校验必填/可选参数 |
| `ToolRegistry` / `ToolInvoker` | 工具目录与执行端口 |

### 治理领域 `domain.governance`

| 类型 | 说明 |
|---|---|
| `WorkspaceKey` | `sha256(normalized cwd)`；USER 全局键为 64 个 `0` |
| `SandboxPolicy` | 工作区根、可写根、是否允许越界读 |
| `PathSandbox` | 纯路径判定：绝对化、规范化、根包含、NUL/非法路径 |
| `PolicyScope / PolicyEffect / ApprovalMode` | 策略枚举 |
| `ToolPolicyKey / ToolPolicySettings / ToolPolicyRule` | 策略聚合与版本 |
| `ToolAccessPolicy` | WORKSPACE > USER > 风险默认 |
| `ToolPolicyRepository` | 查询、插入、CAS 更新端口 |

风险默认值：`LOW → ALLOW`、`MEDIUM/HIGH → ASK`、`CRITICAL → DENY`。
M3 的四个只读工具均为 `LOW`，因此默认无需审批。

### 基础设施 `infrastructure.tool`

```text
infrastructure.tool
├── BuiltInToolCatalog       四个内置工具定义（JSON Schema、风险、超时）
├── CatalogToolRegistry      ToolCatalog -> ToolRegistry
├── BuiltInToolInvoker       虚拟线程、超时、异常包装
├── RealPathResolver         词法沙箱 + toRealPath 物理复核
├── WorkspaceWalker          有界遍历，跳过隐藏/构建目录，不跟随符号链接
├── FileContentClassifier    前 8KB 含 NUL 判定二进制
├── ToolText                 相对路径与截断
└── handler/                 Read / Ls / Grep / Glob
```

- `read`：1-based offset/limit，默认 400 行、最多 2000 行，单行 2000 字符，正文 80k；
- `ls`：深度 ≤3，最多 500 项，正文 60k，目录带 `/` 后缀；
- `grep`：正则搜索，默认 100/最多 500 条，最多 5000 文件、单文件 2MB，片段 300 字符；
- `glob`：默认 200/最多 1000 条，最多遍历 20000 文件，拒绝绝对 pattern；
- 超时取消任务并返回 `TOOL_TIMEOUT`；线程中断返回 `CANCELLED`；
  handler 的领域异常保留错误码，其他异常包装为 `TOOL_EXECUTION_FAILED`。

### 持久化与 API

- `V3__tool_policy.sql`（MySQL / H2）：`(scope, workspace_key, tool_name)` 唯一键，
  `version` 从 1 开始，CAS 更新；
- `ToolPolicyConfigCodec`、`ToolPolicyPO`、`ToolPolicyMapper`、
  `MyBatisToolPolicyRepository`；
- `ToolCatalogApplicationService` 合并工具目录与当前工作区策略，输出 `ToolView`；
- `GET /api/v1/tools?cwd=...` 返回完整 schema、风险、执行模式、超时、`effect` 与
  `requiresApproval`；`cwd` 可省略，非法路径返回 400。

## 关键设计决策

1. **“语法 + 物理”双重路径校验**：`PathSandbox` 只做纯字符串判定，便于跨平台单测；
   `RealPathResolver` 用 `toRealPath()` 识别符号链接与大小写别名，再把真实路径交回
   同一组包含规则。写路径允许目标不存在：解析最近存在祖先的真实路径后拼回缺失段。
2. **工具失败是数据，不是异常**：除“工具未注册”这类编程错误外，所有失败都变成
   `isError=true` 的 `ToolResult`，让模型看到原因并自行纠正，不终止 run。
3. **超时在调用器统一处理**：每个工具在虚拟线程上执行，`Future.get(timeout)` 到期即
   `cancel(true)`；handler 不需要重复实现超时逻辑。
4. **遍历不跟随符号链接**：`ls/grep/glob` 使用不跟随链接的遍历，避免目录环与越界；
   只有 `read` 显式打开文件时解析真实路径。
5. **策略解析与执行分离**：M3 只把 `effect` 暴露给 UI；真正执行时由 M4 的协调器重新
   解析，绝不信任前端回传。审批动作留到 M6，避免只读阶段引入半成品状态机。
6. **工作区键不存原始路径**：`workspace_key` 固定 64 位十六进制，避免长路径进入唯一索引，
   Windows 盘符路径统一小写后再哈希。

符号链接用例在无法创建链接的 Windows 环境通过 JUnit assumption 跳过；

实际运行（demo profile，H2 + Flyway V1–V3，端口 18080）：

- `GET /api/v1/tools?cwd=D:/code/pi-java` 返回 `glob/grep/ls/read`，均为
  `LOW / PARALLEL / ALLOW`，超时与 schema 正确；
- 不传 `cwd` 返回 200；
- `cwd` 含 NUL 返回 400 `INVALID_ARGUMENT`；
- 启动日志确认 Flyway 应用 V3。

## 已知限制

- 尚未接入 Agent Loop，工具只能通过 `ToolInvoker` 直接调用；并行分批由 M4 的
  `ToolExecutionPlanner` 实现；
- 没有审批流程，`ASK/DENY` 目前只是读模型中的效果值；
- 没有写工具与 bash；
- 插件工具合并、白名单与拦截器留到 M5；
- `grep` 使用 Java 正则，不支持 PCRE 特性；单文件超过 2MB 直接跳过；
- 符号链接检测依赖平台能力；无权限创建链接的环境只验证词法与真实路径分支。
