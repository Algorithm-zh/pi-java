# M12：MCP 客户端

> 日期：2026-10-24
> 状态：已完成；`mvn -q verify`（含 repackage）全绿
> 范围：stdio 与 Streamable HTTP 传输、工具动态发现、命名空间、风险映射、断线与超时

## 目标

补上 v0.2 最高杠杆的外部能力面：不重新打包、不改插件契约，就能把现有 MCP 服务器
提供的工具接进 Agent Loop。约束是“外部工具必须和内建工具守同样的规矩”：

- 所有远程工具都进入同一个运行时目录与 run 快照；
- 命名必须稳定、可读，且不能撞上内置/插件工具；
- 风险级别可配置，默认走审批而不是静默放行；
- 超时、断线、远程报错都不能打断 run；
- 配置里只出现环境变量占位符，不保存明文密钥。

## 交付范围

- 配置：`pi.mcp.servers`（`McpSettings`，无数据库迁移），`application.yml` 默认空列表；
- `domain.shared.DomainErrorCode` 新增 `MCP_TOOL_CONFLICT`；
- infrastructure `mcp` 包：
  - `McpException`（`MCP_TRANSPORT`/`MCP_TIMEOUT`/`MCP_PROTOCOL`/`MCP_STREAM_CLOSED`/`MCP_CANCELLED`）；
  - `McpProtocol`、`McpTransport`、`StdioMcpTransport`、`HttpMcpTransport`；
  - `McpClient`、`McpServerConnection`（initialize、initialized 通知、分页 `tools/list`、`tools/call`）；
  - `McpToolNamespace`、`McpRiskMapper`、`McpToolInfo`、`McpCallResult`；
  - `McpToolAdapter`、`McpServerRuntime`、`McpClientFactory`、`McpClients`、`McpHost`；
- `RuntimeToolRegistry` 增加 MCP 目录与 `replaceMcp/removeMcp`，统一冲突检查；
- `RuntimeToolInvoker` 三分派：MCP → 插件 → 内置；
- `McpConfiguration` 装配 `McpHost`，`McpStartupRunner` 启动时连接；
- Web/CLI/SSE 无需改动：工具通过既有目录与管线自然可见。

## 关键设计

- **配置驱动，不落库**：MCP 服务器生命周期跟随进程，避免为外部连接引入表结构与
  恢复语义；远端目录变化要求重启，换来 run 快照与调用目标的一致性。
- **启动隔离**：逐服务器连接与注册，失败只告警；结构错误才在绑定阶段失败，
  避免“写错配置却静默不生效”。
- **命名空间**：远程名清洗为 `ToolName` 合法字符后加 `<server>.` 前缀；超长截断
  带短哈希；注册时校验前缀归属，并与其他来源做冲突检查。
- **默认要审批**：名称启发式只产出 `MEDIUM`/`HIGH`，`CRITICAL` 必须显式配置；
  随后交给 `ToolAccessPolicy` 的默认值（`MEDIUM`/`HIGH` = ASK）。
- **不自动重试**：工具调用可能有副作用；只在传输明确关闭（如 stdio 子进程退出）
  时于下一次调用前重连并重新握手。
- **失败即结果**：所有传输/协议/远端错误都转成 `error=true` 的 `ToolResult`，
  带 `errorCode`、`server`、`mcpTool`，Agent Loop 继续。

### 说明

打包前需停止正在运行的实例：Windows 会锁住 `pi-java-app-*.jar`，导致
`spring-boot:repackage` 无法重命名。调试阶段可加 `-Dspring-boot.repackage.skip=true`
只跑测试，但该模式产出的 jar 没有 `Main-Class`，不能直接 `java -jar`。

## 已知限制

- 不支持 resources、prompts、sampling 与服务端通知，工具目录变更需重启；
- HTTP 传输不做 OAuth，也不自动重试；`Mcp-Session-Id` 仅存内存；
- 远程工具不受路径沙箱约束，只应接入可信服务器；
- 无 MCP 管理 API 与 UI，服务器仍以配置文件为准；
- 同名服务器只能配置一次；stdio 子进程随宿主退出而终止。
