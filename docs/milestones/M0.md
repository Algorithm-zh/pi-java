## 目标

在不写业务代码的前提下，冻结以下内容：

- Maven 模块划分与依赖方向；
- 7 个限界上下文与包结构；
- 6 张业务表与 Flyway 策略；
- 运行时、SSE、审批、压缩、子代理的设计边界；

M0 的产出是后续所有里程碑的“宪法”，而不是一个可用的 agent。

## 关键决策

| 决策 | 原因 |
|---|---|
| 6 个主模块，不建 types/api 模块 | 避免共享内核变垃圾场；HTTP DTO 归 trigger |
| 7 个上下文，不建 subagent/workspace | 子代理复用 session；工作区就是 cwd + sandbox |
| 6 张业务表 | 压缩、审批决策、运行摘要都是 entry；不重复存事实 |
| domain 纯 JDK | 可脱离 Spring/DB 单测；ArchUnit 强制 |
| plugin-api 纯 JDK | 第三方稳定契约；类加载隔离边界清晰 |
| 不引入 Redis | 单机强一致；SSE/审批/run 都在进程内 |
| 手写 LLM Gateway | 控制流式、重试、取消；避免 Spring AI 抽象耦合 |
| 文件 ≤ 300 行、方法 ≤ 50 行 | 防止重新长成不可维护的巨文件 |
