# M5：插件 SDK

> 日期：2026-10-22
> 状态：已完成
> 提交：`feat(plugin): zero-dependency plugin sdk and example`

## 目标

在已经稳定的工具目录与 run 生命周期之上，引入第三方扩展能力：

- 零依赖 `plugin-api`，插件可独立编译、独立打包；
- 每个插件独立 child-first 类加载器，只暴露 JDK 与契约包；
- 安装、启用、停用与启动恢复的完整生命周期；
- 插件工具与内置工具走同一条策略/沙箱管线；
- run 开始时冻结工具快照，插件启停不影响已开始的 run；
- 示例插件可安装、可调用、可停用。

## 交付物

### `pi-java-plugin-api`

| 类型 | 说明 |
|---|---|
| `PiPlugin` | 入口：`descriptor / start / stop` |
| `PluginDescriptor` / `PluginId` | 插件自描述与标识 |
| `PluginContext` | `registerTool`、`log` |
| `ToolSpec` / `PluginTool` | 短名、schema、风险、超时、执行 |
| `PluginToolCall` / `PluginToolResult` | 调用参数与结果 |
| `PluginToolContext` | 工作区、取消令牌、日志、`progress`（M5 空实现） |
| `Registration` | 注册句柄，可重复关闭 |
| `PluginRisk` / `PluginLogger` / `CancellationToken` | 风险映射、日志、取消 |

M5 **没有**命令、hook、拦截器、prompt section、插件消息或自定义 entry 契约。
`PluginContext` 只开放工具注册，避免留下无法执行的占位 API。

### 领域层 `domain.extension`

| 类型 | 说明 |
|---|---|
| `PluginId` | 小写字母/数字/点/连字符，兼作工具名前缀 |
| `ApiVersion` | 解析 `MAJOR` 或 `MAJOR.MINOR`，规范化比较 |
| `PluginPackage` | jar 检查结果 |
| `PluginArtifact` | 落库的路径、版本、checksum、config |
| `PluginInstallation` | 聚合根与状态迁移 |
| `PluginStatus` | `INSTALLED / ACTIVE / DISABLED / FAILED` |
| `PluginCompatibilityChecker` | API 主版本、工具名前缀、重名检查 |
| `PluginRepository` / `PluginPackageInspector` / `PluginRuntime` | 端口 |

### 基础设施

```text
infrastructure.plugin
├── PluginApiClassLoader     只暴露 JDK + plugin-api 的父加载器
├── PluginClassLoader        child-first 插件加载器
├── PluginJarInspector       清单、入口类、大小、checksum、打包 API 检查
├── PluginHost               加载/回滚/停用/关闭，实现 PluginRuntime
├── PluginContextImpl         注册收集与关闭
├── PluginToolAdapter        插件工具 → ToolDescriptor/ToolResult
├── PluginToolExecutor       工具名 → 插件句柄分派
├── RuntimeToolRegistry      内置 + 插件工具的不可变目录
└── RuntimeToolInvoker       插件工具调用入口
```

### 应用层与 HTTP

- `PluginApplicationService`：安装、启用、停用、查询、启动恢复；
- `PluginStartupRunner`：应用启动后重新加载所有 `ACTIVE` 记录；
- `GET/POST /api/v1/plugins`、`POST /{id}/enable`、`POST /{id}/disable`；
- V4 `pi_plugin` 与 MyBatis 仓储。

### run 级工具快照

`ToolRegistry` 增加默认 `snapshot()`；`RunRuntime.reserve` 在 run 开始时冻结目录，
`AgentLoopService`、`TurnPipeline` 与 `ToolCallCoordinator` 全部使用该快照：

- 插件停用不会让正在执行的 run 突然失去工具；
- 新 run 也不会看到已停用的工具；
- 快照是 `ToolCatalog` 的不可变副本，不持有插件对象本身。

## 关键设计决策

1. **安装与加载分离**：安装只校验 jar 并落库，不执行插件代码；显式 enable 才创建
   类加载器并调用 `start`。这样上传/登记插件不会产生副作用。
2. **启用时重新验证**：安装后 jar 可能被替换，因此 enable 重新检查 id、版本、
   API 版本与 SHA-256，不一致直接拒绝。
3. **停用不等待**：没有活跃调用计数。停用立即从实时目录移除，但把插件实例、
   工具句柄与类加载器移入 retired 列表，直到进程退出才 `stop()` 和关闭。
   已开始的 run 依靠旧快照继续完成；代价是停用插件的内存不会立即释放。
4. **失败回滚**：`start` 异常、schema 非法、工具重名、descriptor 与清单不一致时，
   关闭注册、调用 `stop()`、关闭类加载器，并确保实时目录不残留。
5. **未知工具回显原始名**：端到端测试发现，用占位名 `unknown` 生成错误结果会破坏
   toolCall/toolResult 配对。修复为回显调用名，并在 `ToolCallBlock` 构造时校验
   `ToolCallId` 与 `ToolName`，从源头阻止非法名进入会话日志。
6. **Fake demo 支持任意工具**：`/tool <name> <json>` 让零 API Key 的 demo 也能
   验证插件链路，而不是只测只读内置工具。

## 实际运行

Java 21，端口 18080，H2（先内存库、后用临时文件库验证重启恢复）：

1. `POST /api/v1/system/info` 返回版本与工作区；
2. `POST /api/v1/plugins` 安装示例插件，返回 `201`、`status=INSTALLED`；
3. `POST /api/v1/plugins/com.piagent.example.hello/enable` 返回 `200`、`ACTIVE`；
4. `GET /api/v1/tools` 返回
   `com.piagent.example.hello.greet` 与四个内置工具；
5. 新建会话并发送 `/tool com.piagent.example.hello.greet {"name":"pi"}`，
   SSE 返回 `tool.completed`，`content=你好，pi！`，`details.pluginId` 正确；
6. `POST .../disable` 后工具列表只剩内置工具；再次调用得到
   `工具未注册: com.piagent.example.hello.greet`，run 仍以 `run.completed` 结束；
7. 用临时文件库重新安装并启用，重启进程后插件仍为 `ACTIVE`，工具自动恢复。

## 已知限制

- 没有插件 Web UI，安装/启停只能通过 REST/curl；
- 没有热重载与卸载接口；停用插件的实例和类加载器保留到进程退出；
- 插件配置只落库不读取；
- 插件没有权限声明，拥有与宿主相同的 JVM 权限；
- 插件工具只有在 `risk=LOW` 时默认放行；`MEDIUM/HIGH` 在 M4/M5 会因缺少审批
  直接返回“需要用户审批”的错误结果，`CRITICAL` 默认拒绝；M6 接入审批后才会执行；
- 插件命令、hook、拦截器、prompt section 均未实现，文档不再把它们描述为 M5 能力。
