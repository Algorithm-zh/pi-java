# M11：CLI 入口与 v0.1.0 收尾

> 日期：2026-10-24
> 状态：CLI 已完成并通过构建与手工冒烟；MySQL smoke 与 `v0.1.0` tag 待用户环境确认
> 范围：同一可执行 jar 的 CLI 模式、命令树、流式与审批交互、只读命令

## 目标

Web 已经可用，但在服务器、脚本与 CI 里需要一种不启动浏览器的入口。本里程碑把
CLI 加在同一个 Spring 容器上，而不是复制一套业务逻辑：

- 同一个 jar：无参数 / `serve` 启动 Web，子命令进入 CLI；
- CLI 与 Web 共用数据库、Flyway、模型档案、工具、插件、技能与审批管线；
- `run` 支持流式输出、交互审批、`--json` 与稳定退出码；
- `chat` 提供多轮对话、压缩、模型切换与分支查看；
- 只读命令覆盖会话、模型与工具目录；
- 不新增任何持久化路径，不绕过应用层用例。

## 启动模式

`CliMode` 是唯一的模式判定点：

| 首参数 | 模式 |
|---|---|
| 无参数 | Web（保持历史用法） |
| `serve` | Web；`--port`/`--profile` 转为 Spring 参数 |
| `--server.port=...` 等 Spring 参数 | Web |
| `--help`、`-h`、`--version`、`-V` | CLI 根帮助/版本 |
| `run`、`chat`、`sessions`、`models`、`tools` | CLI |

CLI 模式由 `CliLauncher` 以 `WebApplicationType.NONE` 启动同一个
`PiJavaApplication` 容器，执行完毕后关闭容器并返回退出码。

```bash
java -jar pi-java-app/target/pi-java-app-0.1.0-SNAPSHOT.jar --help
java -jar pi-java-app/target/pi-java-app-0.1.0-SNAPSHOT.jar run "总结 README"
java -jar pi-java-app/target/pi-java-app-0.1.0-SNAPSHOT.jar chat --cwd D:/code/demo
java -jar pi-java-app/target/pi-java-app-0.1.0-SNAPSHOT.jar serve --port 8081
```

## 命令与交互

```text
pi run      [MESSAGE] [--cwd PATH] [--model ID] [--thinking LEVEL]
            [--title TITLE] [--session ID] [--json] [--timeout SECONDS] [--approve]
pi chat     [--cwd PATH] [--model ID] [--thinking LEVEL] [--session ID] [--title TITLE]
            [--plain]
pi sessions list [--cwd PATH] [--limit N]
pi sessions show ID
pi models   list
pi tools    list [--cwd PATH]
pi serve    [--port PORT] [--profile demo|mysql] [Spring 参数]
```

`run` 的退出码：

| 码 | 含义 |
|---|---|
| `0` | 完成（`COMPLETED`） |
| `1` | 运行失败、超时或收尾失败 |
| `2` | 参数/工作目录/会话 ID 不合法 |
| `3` | 至少一次审批被拒绝（含 EOF 默认拒绝） |
| `4` | 用户取消 |

`--json` 时 stdout 只有一个 JSON 对象，会话横幅、审批提示与诊断都走 stderr；
超时会先请求取消，再给 5 秒收尾时间。

`chat` 在真实终端里默认进入 JLine 交互界面：方框输入区、彩色流式输出、
`Tab` 补全斜杠命令、`↑/↓` 翻历史；`Ctrl+C` 运行中取消当前 run，空闲时连按
两次退出；`Ctrl+D` 随时退出。管道、重定向、测试环境或 `--plain` 退回逐行
模式，输出与旧版一致。两种模式都支持 `/help`、`/exit`、`/quit`、`/abort`、
`/compact`、`/model`、`/tree`、`/session` 与 `/skill:名称`。

## 关键设计

- **主线程消费事件**：run 线程只往 `LinkedBlockingQueue<RunEvent>` 放事件，
  审批提问、`/abort` 读取和结果输出都在调用线程完成，终端的读写始终只有一个线程；
- **输入流注入**：picocli 4.7 只管理 out/err，`CliTerminal` 用 ThreadLocal
  在执行期间绑定 stdin，测试可传入内存流；
- **命令 Bean 是 prototype**：Spring 单例会让 picocli 复用上次解析的选项值
  （`--json`、MESSAGE 残留），所以 10 个命令类全部使用 `SCOPE_PROTOTYPE`；
- **编码跟随原生控制台**：CLI 输出使用 `CliCharset` 选择的编码（默认
  `native.encoding`，Git Bash 等 UTF-8 环境自动切换，`PI_CLI_ENCODING` 可覆盖），
  避免 GBK 终端把 UTF-8 字节显示成乱码；TUI 通过 JLine 的 `terminal.writer()`
  写 Unicode，绕开代码页；
- **TUI 与行模式共用一套语义**：斜杠命令、审批、退出码由 `CliChatSupport` /
  `CliRunExecutor` / `ApprovalPrompt` 共享，TUI 只替换渲染与提问方式；
- **Ctrl+C 走信号**：JLine 在 Windows 与 POSIX 都按 ISIG 把 Ctrl+C 转成
  `Signal.INT`，不会交给读取方；`TuiInterrupts` 注册信号处理器取消 run，
  审批读行期间暂停并交还 `LineReader`；
- **日志走 stderr**：启动前把 `System.out` 指向 stderr，并通过命令行参数把
  `logging.level.root` 压到 WARN，避免 Hikari/Flyway 的 INFO 污染 `--json`；
- **退出前关闭 run**：`CliRun.close()` 退订事件并释放资源，容器随 try-with-resources 关闭。

| `trigger/cli/ApprovalPrompt` | 审批端口（approve/deny/no-input 三态） |
| `trigger/cli/SessionsCommand` 等 | 只读命令 |
| `trigger/cli/CliSessionService` | 会话准备、cwd/ID/思考级别校验、默认模型 |
| `trigger/cli/CliRunService` / `CliRun` | 启动 run 并订阅事件 |
| `trigger/cli/CliRunExecutor` | 事件循环、审批、超时、退出码与 JSON |
| `trigger/cli/CliRunRenderer` | 流式文本/思考、工具摘要、失败与压缩状态 |
| `trigger/cli/CliProjection` / `CliText` | entry 单行摘要与文本截断 |
| `app/cli/CliLauncher` | 非 Web 容器启动、流重定向与编码 |
| `app/PiJavaApplication` | 双模式入口 |

- `--approve` 自动批准并落盘；

- ConPTY 下的交互界面：横幅与方框输入区正常、`/he<Tab>` 补全为 `/help`、

- `serve --port 9099` 能启动并响应 `/api/v1/system/info`，停止后端口释放。

## 已知限制

- 每次 CLI 启动都要初始化 Spring 容器与 Flyway，首次连接文件库约需数秒；
- `pi models add`、`pi plugins *`、`sessions fork/resume` 尚未进入 CLI，
  可继续使用 Web 设置中心或 REST；
- CLI 审批只能逐条回答，没有 Web 的倒计时与批量队列界面；
- TUI 的命令历史只保存在当前进程内，未写入历史文件；
- ConPTY 自动化无法注入 Ctrl+C（原生 JLine 收敛为 `Signal.INT`，pty 也收不到），
  因此“运行中取消 / 空闲连按两次退出”只由 `TuiInterruptsTest` 触发信号验证，
  未在真实键盘上回归；`Ctrl+D` 与 `/exit` 已在 ConPTY 验证；
- v0.1 无鉴权，`--approve` 只应在可信工作区使用；
- MySQL smoke 需要本机 MySQL 实例，尚未在本次环境验证；
- `v0.1.0` tag 需用户确认后创建。
