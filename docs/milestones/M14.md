# M14：计划、待办与自动验证

> 日期：2026-10-26
> 状态：已完成；隔离副本中 `mvn -q verify` 全绿，8080 实例未受影响
> 范围：计划模型与 `PLAN` entry、`todo` 工具、自动验证命令与失败回写、Web/CLI 展示

## 目标

让代理从“改完就说完成”变成“有计划、有验证”：

- 代理能把任务拆成少量待办，并在执行中更新状态；
- 用户能随时看到进度，重启或切换会话后仍然存在；
- 改过工作区的 run 在收尾前自动跑一次项目验证；
- 验证失败时把真实错误交回模型，只重试一次；
- Web 与 CLI 共用同一套数据与事件。

## 交付范围

- `domain.plan`：
  - `Plan`、`PlanItem`、`PlanItemStatus`；
  - 最多 20 条、最多一条 `in_progress`、内容去空白且 ≤200 字；
- `domain.session`：
  - `EntryType.PLAN / VERIFICATION`；
  - `PlanPayload(runId, items)`、`VerificationPayload(runId, command, passed,
    exitCode, timedOut, truncated, durationMs, output)`；
  - 投影只把最新 `PLAN` 作为当前计划，两者都不进入模型上下文；
- `application.plan`：
  - `SessionPlanService`：替换计划、写 entry、发布 `plan.updated`；
  - `SessionPlanSnapshot`：当前计划 + 最近一次验证；
- `application.verify`：
  - `VerificationOptions`（`pi.verify.*`）；
  - `VerificationService`：执行命令、写 `VERIFICATION` entry、失败回写用户消息；
- `application.agent`：
  - `RunVerificationStep`：改过文件且准备收尾时验证一次；
  - `AgentLoopDependencies`：循环依赖集中为值对象；
- `infrastructure`：
  - `TodoToolHandler` 与 `todo` 工具注册；
  - `ShellVerificationRunner`：系统 shell、超时终止进程树、输出截断；
  - `VerificationConfiguration`；`AgentRuntimeConfiguration` 装配循环依赖；
- `trigger`：
  - `GET /api/v1/sessions/{id}/plan`；
  - SSE `plan.updated`、`verification.completed`；
  - CLI `[待办]` / `[验证]` 摘要、TUI 短行、`/plan` 命令；
- Web：
  - 输入框上方待办面板（进度环、当前项、展开列表、验证状态与输出）；
  - 历史消息中的“待办更新”与“自动验证”折叠卡片；
  - 刷新或重连后从 `/plan` 恢复；
- 持久化：复用 `pi_session_entry`，无数据库迁移。

## 关键设计

- **最新快照，不做增量**：每次 `todo` 都写完整 `PLAN` entry；分支上最后一条即当前
  计划，切分支/撤销/重启都自然复用已有投影。
- **工具单一写入口**：HTTP 只读，计划只能由模型经 `todo` 维护，避免人工与模型
  两份计划互相覆盖。
- **整表替换**：`todos` 是完整清单，清空即传空数组；比增量补丁更容易校验。
- **验证绑定 run**：只有本次 run 真的执行过写类工具才验证；只读任务不会白跑测试。
- **失败回写一次**：失败输出作为用户消息进入上下文，模型修复后同一 run 再收尾；
  `attempts > 0` 后不再回写，避免验证失败导致无限循环。
- **验证命令不进审批**：命令来自用户配置而非模型；执行器仍限制超时与输出长度。
- **失败不打断 run**：验证器启动失败、超时、回写失败都只记日志，run 正常收尾。
- **依赖集中**：循环服务协作者已超过 6 个，集中为 `AgentLoopDependencies`，
  由基础设施配置类装配。

## 已知限制

- 每个 run 只验证一次、失败只回写一次；需要多轮验证时要模型显式调用 `bash`；
- 计划只支持整表替换，没有增量接口；
- 验证命令是单条 shell 命令，不支持并行矩阵；
- 失败输出进入用户消息，会占用上下文 token；
- 客户端断开不会停止服务端验证，结果仍会写入日志。
